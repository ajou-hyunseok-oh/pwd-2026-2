# 원본 PDF 분석과 2026년 6주차 업데이트 검토

확인일: **2026-10-15 KST**. 원본은 `[PWD Week4] Node.js Express 프레임워크를 이용한 웹 서버 개발.pdf` 27쪽이다. 표지와 반복 머리말의 2025학년도 표기를 기준으로 전년도 자료로 식별했다. PDF 메타데이터에 생성일·수정일은 없다. 파일 해시·원본 크기·이미지 위치·링크는 [manifest.json](manifest.json)에 보관했다.

검토 결과, **원본의 서버→HTTP/REST→Express→계층 구조→테스트·배포 범위와 Foodmap 사례는 유지할 수 있다.** 2026년 강의는 Node.js 24 LTS와 Express 5.3.0을 실행 기준으로 삼고, HTTP·Node.js·멱등성의 기존 설명 오류를 고쳐야 한다. Render의 무료 조건과 실습 연결 정보도 구체화해야 한다. 아래에서 실제 연도 변화와 기존 설명의 보완을 구분한다.

Express 5.3.0은 응답 헤더 처리와 의존성 보완을 포함한다. 입문 예제의 라우트·JSON·미들웨어 작성 방식은 그대로 사용할 수 있다. 원본이 이미 Express 5.1.0이므로 **Express 4→5의 변화 전체를 올해 새 기능으로 설명하면 안 된다.** [공식 5.3.0 릴리스](https://github.com/expressjs/express/releases/tag/v5.3.0), [Express 지원 정책](https://expressjs.com/en/support/), [확인 시점 npm 데이터](current-facts-2026-10-15.json).

Node.js 24.22.0은 2026-10-14에 나온 LTS 릴리스다. 24의 유지보수 단계 전환 예정일은 10월 20일이며, 그 이후에도 LTS 지원은 계속된다. 버전 선택은 최신 메이저 번호와 구분한다. [24.22.0 공식 릴리스](https://nodejs.org/en/blog/release/v24.22.0), [공식 지원 일정](https://raw.githubusercontent.com/nodejs/Release/main/schedule.json).

Render의 Node 기본값은 서비스 생성일에 따라 다르다. 예제 폴더를 별도 저장소로 옮기는 경우에도 명시한 버전과 `engines`를 함께 유지한다. [Node 버전 설정](https://render.com/docs/node-version), [모노레포의 Root Directory](https://render.com/docs/monorepo-support).

## 3. Render 설명: 현재 조건의 보완

원본의 `프로젝트 1개 무료, 로그/헬스체크, 수평 스케일링 지원`은 무료·유료 기능의 경계가 불분명하다. 다음은 **현재 정책을 확인한 보완 사항이며, 모두 2026년에 신설되었다는 판단은 아니다.**

- 무료 웹 서비스는 요청이 15분 없으면 유휴 중지. 다음 요청에는 재기동 대기 가능.
- 무료 인스턴스 시간은 워크스페이스당 월 750시간 공유. 프로젝트 1개 무료라는 표현과 구분.
- 로컬 파일은 재배포·재시작·유휴 중지 때 보존되지 않음. 무료 웹 서비스에는 영구 디스크 연결 불가.
- 무료 웹 서비스의 여러 인스턴스로의 확장은 지원하지 않음.
- 실제 배포 설정은 Web Service, 올바른 Root Directory, `npm ci`, `npm start`, `PORT`, `0.0.0.0`, `/health`, 허용 클라이언트 출처로 제시.

강의 본문에는 유휴 중지·공유 시간·메모리 데이터 초기화를 표시하고, 세부 운영 조건은 예제 안내에 둔다. 요금표를 강의의 고정 사실로 복사하지 않는다. [무료 서비스 공식 조건](https://render.com/docs/free), [Express 배포 공식 절차](https://render.com/docs/deploy-node-express-app), [포트 바인딩](https://render.com/docs/web-services#port-binding).

이 교정들은 올해 문법이 바뀌어서 생긴 수정이 아니다. 원래의 일반화·누락을 바로잡는 내용이다. HTTP의 멱등성·메서드·HTTPS는 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), 캐시는 [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html), REST는 [Fielding 원문](https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm), Node.js 실행은 [공식 런타임 소개](https://nodejs.org/en/learn/getting-started/introduction-to-nodejs)와 [이벤트 루프 설명](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick)을 기준으로 대조했다.

Express 5의 Promise 거부 자동 전달, 파싱 전 `req.body`의 undefined, 기본 simple 쿼리 파서, 와일드카드 경로 표기는 4.x 예제를 가져올 때의 호환성 검토 항목이다. 현재 예제는 기본 경로·문자열 쿼리 검증·명시적 JSON 파서·최종 오류 미들웨어를 사용한다. CommonJS는 계속 유효하며 ESM으로 바꿔야 하는 상황은 아니다. [공식 5.x 이행 안내](https://expressjs.com/en/guide/migrating-5/), [오류 처리](https://expressjs.com/en/guide/error-handling/), [CORS 동작](https://expressjs.com/en/resources/middleware/cors/).

## 7. 정리된 학습 텍스트와 순서

원본 텍스트의 정의·역할·관계를 다음과 같이 정리한다. 실제 본문은 현재 `scripts/slide_body.py`의 한영 데이터를 기준으로 관리한다.

1. **서버 구조와 실행 환경**: 클라이언트-서버는 요청과 처리의 역할 분리. Node.js는 브라우저 밖 JavaScript 런타임, V8은 그 안의 실행 엔진. 비동기 I/O와 이벤트 루프는 대기 작업과 콜백 실행의 관계로 설명.
2. **메시지와 데이터**: HTTP는 요청·응답의 의미, HTTPS는 TLS 보호. 메시지의 메서드/대상/헤더/본문과 상태 코드를 구분. JSON 형식과 값↔문자열 변환을 별도로 학습.
3. **리소스와 요청 의미**: URI로 대상을 식별하고 표현을 교환. 메서드는 작업 의미, 멱등성은 동일 요청 반복의 의도된 효과. 캐시와 같은 응답을 보장하는 개념으로 혼합하지 않음.
4. **Express 처리**: 프로젝트·CommonJS·서버 시작 뒤에 라우트와 입력 추출. 미들웨어 제어권·JSON 파싱·검증·오류 처리 순서로 실제 요청을 연결.
5. **역할 분리**: 모델은 저장 접근, 서비스는 업무 규칙, 컨트롤러는 HTTP 변환, 라우터는 경로 연결. server와 app을 분리해 테스트에서 앱 재사용.
6. **테스트·배포·브라우저**: 요구사항을 실패 테스트로 표현하고 단위/HTTP 테스트 실행. 버전·환경변수·포트·출처를 맞춘 뒤 React에서 응답 상태와 JSON 처리.

이 순서는 원본에서 MVC/TDD가 Express 구현보다 앞선 부분을 학습 의존성에 맞춰 이동한 것이다. 원본의 새 주제를 임의로 확대하지 않으며 DB·인증 구현은 07 이후 자료에 채우지 않는다.
