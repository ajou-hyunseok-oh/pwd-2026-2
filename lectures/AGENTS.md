# 강의 작성 하네스

05 이후 강의의 작성·수정에는 먼저 [공통 작성 기준](authoring/README.md)을 읽는다. 01~04에서 확정한 편집 결과를 기준으로 삼으며, 새 회차마다 문체·레이아웃·검증을 다시 설계하지 않는다.

**포맷과 내용의 기준을 구분한다.** 06은 사용자의 최신 지시에 따라 05주차의 슬라이드 디자인·본문 정리 형식을 적용하고, 제목·학습 내용·순서·이미지·표·코드·실습은 제공된 원본 PDF를 따른다. 표지는 2026학년도 2학기·6주차로 표시한다. 원본 요소를 개별 추출해 슬라이드별로 최적화해 배치하며 페이지 전체 SVG나 원본 좌표 고정으로 05의 형식을 대체하지 않는다.

원본 보존은 제목·개념·예제·표의 모든 행과 열·그림의 구성 요소와 연결·학습 맥락의 보존을 뜻한다. 배치·여백·글꼴·설명의 위계·코드 서식은 05의 형식으로 정리한다. 내용 보존을 이유로 디자인을 없애거나, 디자인 통일을 이유로 내용을 바꾸지 않는다. 새 개념 추가·제목 분할·사례 교체는 별도 요청 없이 하지 않는다. 최신 정보 검토는 별도 제안으로 기록한다.

- 작성 원본과 생성기를 먼저 확인하고 원본을 수정한다. 생성된 HTML만 고치지 않는다.
- 강의 표지는 [표지 공통 형식](authoring/cover.md)에 따른다. 단일 회차 덱은 주차형, 독립 주제별 덱은 주제형을 사용하고 공식 과목명·학기·회차를 확인한다.
- 신규·재작성 본문은 [1개념 1슬라이드](authoring/one-concept.md)를 따른다. 개념별 제목·서브타이틀을 먼저 작성한다. 05의 현재 화면 26 이후는 `05/scripts/title_outline.py`의 제목 목록을 기준으로 본문을 작성하며, 기존 복합 본문을 새 제목 아래 그대로 붙이지 않는다.
- 본문은 [개념 설명 작성 기준](authoring/body-explanation.md)에 따라 개념·구성 요소의 역할·관계와 구조를 일반화해 설명한다. 코드는 이를 보여주는 사례이며, 강사가 코드를 짚으며 말할 해설로 본문을 대신하지 않는다. 코드 없이 읽어도 핵심 개념과 구조를 이해할 수 있는지 검토한다.
- 확정된 제목·순서·학습 범위·사례를 보존한다. 모든 장에 코드나 일정한 항목 수를 강제하지 않는다.
- [학습 순서 검토](authoring/one-concept.md#학습-순서와-선수-개념)에 따라 본문·표·코드가 아직 배우지 않은 개념을 먼저 정의하거나 사용 규칙을 설명하는지 확인한다. 뒤 개념이 예제 이해에 필요하면 이미 배운 개념으로 예제를 단순화하거나 도식·표로 바꾼다. 제목을 나누는 것만으로 학습 순서 검토를 대신하지 않는다.
- 원본의 디자인까지 유지하라고 지정한 가져오기 구간은 공통 스타일로 변환하지 않는다. 05의 첫 번째 챕터는 04 React 덱 24장 전체이며, 원본 대조 검사를 유지한다.
- 설명은 **개념 - 짧은 정의**와 그 아래 세부 설명으로 구성한다. 비교는 표, 순서는 흐름으로 유지한다.
- 명사형 중심의 짧은 구문을 사용한다. 제작 지시·다음 내용 예고·본문을 되풀이하는 하단 요약을 넣지 않는다.
- `packages/web-deck/authoring.css`를 재사용한다. 회차별 CSS에는 해당 내용에 필요한 차이만 둔다.
- 출처는 기본적으로 숨김 노트와 자료 기록에 보관한다. 학습 활동에 필요한 링크만 해당 본문에 둔다. 02의 특정 참고 링크 위치를 모든 강의의 필수 푸터로 확대하지 않는다.
- KO/EN과 HTML 기본값을 함께 갱신하고 공용 검사 및 실제 발표·인쇄·모바일 화면을 확인한다.
- `npm test --prefix packages/web-deck`에는 작성 하네스 검사가 포함된다. 통과만으로 내용 검토를 대신하지 않는다.

07~13의 한 장짜리 골격은 신규 본문을 작성할 때 하네스를 적용한다. 기존 01~04의 형식과 회차별 예외를 소급해서 일괄 변경하지 않는다.
