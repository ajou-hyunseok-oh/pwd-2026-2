지침 작성 모범 사례

문맥 비대화를 막고 규칙 준수율과 안전성을 높이는 작성 기준

간결한 지도 역할 - 모든 작업에 필수인 정보만 150~200줄 내 유지
  • 빌드 · 테스트 명령과 코드에서 추론 불가한 제약만 선별 기재
  • 세부 문서는 본문에 복사하지 않고 경로 포인터로 연결
권고와 강제의 분리 - 보안 경계는 지침 대신 시스템 도구로 차단
  • Markdown 지침은 권고이므로 비밀파일 · 위험 명령 차단에 한계
  • 절대 금지는 PreToolUse 훅 · 권한 설정 · 샌드박스 규칙으로 강제

AGENTS.md / CLAUDE.md · 간결한 지침 예시

# Project Guidelines
- Package manager: pnpm (do not use npm)
- Verify changes: `pnpm test` before commit
- API schemas: follow `docs/api.md`

# Hard Boundaries
- Block `.env` reads via permissions/hooks

에이전트 스킬 작성 표준

agentskills.io 오픈 규격과 점진적 공개 3단계 구조

패키지 디렉터리 - SKILL.md와 선택적 실행 · 참고 자원의 묶음
  • 공통 경로 .agents/skills/<name>/ 또는 도구별 .claude · .gemini/skills/
  • scripts/(코드) · references/(참고 문서) · assets/(템플릿) 분리
점진적 공개 - 필요 시점에만 본문과 자원을 불러 문맥 절약
  • 시작 시 name · description만 등록하고 일치 시 SKILL.md 본문 로딩
  • 실행 시 필요한 scripts/ · references/ · assets/ 파일만 추가 로딩

.agents/skills/pr-review/SKILL.md · 표준 형식

---
name: pr-review
description: >
  Review PRs for test and security gaps.
  Use when asked to review diffs.
  Do not use for trivial typo fixes.
compatibility: Requires git and Node.js 22+
---

1. Inspect diff and run `scripts/check.sh`.
2. Check items in `references/checklist.md`.

좋은 스킬 설계 원칙

발견 정확도 · 문맥 효율 · 반복 검증을 높이는 작성법

트리거 description - 할 일과 제외 상황을 함께 명시
  • 실행할 작업과 "쓰지 말아야 할 상황"을 적어 오작동 방지
  • "PROACTIVELY" 강제 문구나 도구 전용 변수 의존 지양
반복 검사 분리 - 정해진 계산·검증은 스크립트로 위임
  • 파싱·포맷·응답 검사는 scripts/로, 판단은 모델이 담당
평가 기반 보완 - 스킬 없이 먼저 실행 후 최소 규칙 추가
  • 스킬 없이 실행해 실패한 부분만 보강하고 다시 검증

SKILL.md 작성 사례 · 나쁜 예시 vs 표준 이식형 예시

# Bad: pushy prompt + vendor-specific variables
description: USE PROACTIVELY on every edit!
Run: python ${CLAUDE_SKILL_DIR}/check.py $ARGUMENTS

# Good: clear trigger + exclusion + relative path
description: >
  Validate REST routes and error codes on API edits.
  Do not use for CSS styling or docs changes.
Run: node scripts/verify-api.mjs

# Ajou FoodMap Server Guidelines (AGENTS.md)
## Map & Checks (npm only · Node 24)
- Code: src/routes/, src/middleware/, supabase/schema.sql
- Tests: tests/ (Jest API + PGlite SQL)
- Verify: npm run typecheck && npm test && npm run build

## Core Invariants
- Verify JWT via db.auth.getUser() + active profiles row
- Order: isAuthenticated -> requireAdmin (401 / 403)
- Keep SUPABASE_SECRET_KEY stateless & RLS (service_role)

# Tool Blocks (.claude/settings.json · .geminiignore)
- Deny Read/Edit/Write on .env* (allow .env.example)

name: server-auth-route-check
description: >
  Verify Express guards (isAuthenticated, requireAdmin),
