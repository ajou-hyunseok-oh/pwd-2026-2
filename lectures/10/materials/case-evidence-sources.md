# 10주차 Chapter 03 보안 사고 사례 근거 및 원인 검증

10주차 Chapter 03(주요 웹 취약점과 방어 원리)에 인용된 모든 보안 사고 사례가 **실제로 해당 슬라이드에서 설명하는 취약점·원인으로 발생했는지** 공식 발표, CVE, 언론 보도를 통해 검증한 기록이다.

- **원칙**: 기술적 원인이 공식 발표나 신뢰할 수 있는 분석으로 확인되지 않은 사고(예: 구 인터파크투어, 강남언니, 전주대 AHA, EU 기관 AI 공격의 세부 침입 기법 등)는 특정 취약점의 원인 사례로 끼워 맞추지 않고 제외했다.

---

## 슬라이드별 사례 근거 매핑

### 09. 객체 수준 인가 결함 (BOLA / IDOR) — `broken-object-auth`
- **슬라이드 설명 취약점**: 인증(로그인) 여부와 무관하게 URL·파라미터의 객체 ID만 변조하여 타인의 데이터에 접근하는 접근 통제 실패(BOLA/IDOR)
- **선정 사례 1 — 한국파파존스 개인정보 노출 (2025년 6월 조사 착수)**
  - **확인된 원인**: 홈페이지 주문 조회 페이지 URL 끝자리(주문번호 파라미터) 숫자만 임의로 변경해도 별도 로그인·권한 검증 없이 타인의 주문 내역·주소·카드정보·공동현관 비밀번호 등이 노출된 파라미터 변조(접근제어 미비) 결함 (`2017.01~2025.06`, 약 3,730만 건 추정).
  - **근거**: 개인정보보호위원회 현장 조사 착수 발표(2025-06-26), 데일리시큐·ZDNet Korea 등 보도.
- **선정 사례 2 — 호주 옵투스(Optus) API 유출 (2022년 9월)**
  - **확인된 원인**: 외부에 노출된 미인증 API 엔드포인트에서 사용자 ID를 순차 변조(IDOR)하여 약 1,000만 명 고객 정보 스크래핑.
  - **근거**: CISA API 보안 권고 및 호주·글로벌 보안 보도.

### 10. 입력 검증과 SQL 인젝션 — `input-and-sqli`
- **슬라이드 설명 취약점**: 사용자 입력이 SQL 명령문 구조로 해석되어 DB 조회·조작·세션 탈취로 이어지는 SQL 인젝션
- **선정 사례 1 — 여기어때 개인정보 유출 사고 (2017년 3월)**
  - **확인된 원인**: 마케팅센터 웹페이지의 SQL 구문 검증 미흡(SQL 인젝션)으로 DB 내 관리자 세션 ID를 탈취해 관리자 페이지에 우회 접속, 99만여 건(중복 포함 약 340만 건) 유출.
  - **근거**: 미래창조과학부·방통위·KISA 민관합동조사단 발표 (`korea.kr`, 보안뉴스 보도).
- **선정 사례 2 — Progress MOVEit Transfer 연쇄 유출 (2023년 5월, CVE-2023-34362)**
  - **확인된 원인**: 웹 애플리케이션의 미인증 SQL 인젝션 제로데이 취약점을 CL0P 랜섬웨어 그룹이 악용해 전 세계 1,000여 개 이상 기관·기업 데이터 유출.
  - **근거**: NVD `CVE-2023-34362`, 미국 CISA·FBI 공동 보안 권고.

### 11. XSS와 제3자 스크립트 실행 통제 — `xss-and-script-control`
- **슬라이드 설명 취약점**: 신뢰할 수 없는 사용자 입력이나 변조된 외부 스크립트가 방문자 브라우저에서 JavaScript로 실행되는 위협과 출력 이스케이프·정제·CSP 방어
- **선정 사례 1 — 트위터 팃덱(TweetDeck) XSS 웜 (2014년)**
  - **확인된 원인**: 트윗 입력 필터링 누락으로 발생한 저장형 XSS가 열람자의 팃덱 브라우저에서 악성 스크립트를 실행해 자동 리트윗으로 확산(이후 Electron 앱 CSP 도입 계기).
  - **근거**: 트위터/보안 커뮤니티 기술 분석 및 보도.
- **선정 사례 2 — Optimizely Web Experimentation 공급망 JS 삽입 (2026년 11월)**
  - **확인된 원인**: 계정 가입 흐름 취약점으로 고객 계정을 사칭해 `Project JavaScript` 필드에 악성 스크립트를 삽입, 178개 고객사 사이트 방문자 브라우저에서 지갑 변조·카드 스키밍 실행(입력 XSS와 구분되는 제3자 스크립트 변조이나 동일한 브라우저 실행 통제·CSP·무결성 감시 교훈).
  - **근거**: Optimizely 공식 보안 공지(2026-11-19), Report URI·Upwind Security 분석.

### 12. 웹 출처 · 동일 출처 정책과 CORS — `origin-sop-cors`
- **슬라이드 설명 취약점**: 서버가 요청 `Origin` 헤더를 검증 없이 `Access-Control-Allow-Origin`에 반사하고 자격증명(`Credentials`)을 허용해 다른 출처에서 민감 응답을 읽을 수 있는 CORS 오설정
- **선정 사례 — 미 국방부(DoD) HackerOne 버그바운티 & 핀테크 API 오설정 연구**
  - **확인된 원인**: 특정 API 경로가 임의의 `Origin` 값을 그대로 허용 헤더에 반사하여 인증된 응답의 교차 출처 읽기가 가능했던 고위험 CORS 오설정 보고 및 패치.
  - **근거**: HackerOne 공개 리포트(DoD), Outpost24 CORS 연구 분석.

### 13. CSRF와 쿠키 보호 속성의 한계 — `csrf-and-cookie-attrs`
- **슬라이드 설명 취약점**: 로그인된 사용자의 브라우저가 조건에 맞는 쿠키를 자동 첨부해 공격자가 의도한 상태 변경 요청을 전송하는 CSRF
- **선정 사례 1 — 페이스북 계정 탈취 CSRF 버그바운티 (2019년)**
  - **확인된 원인**: 특정 엔드포인트의 CSRF 방어 우회로 피해자가 악성 링크를 여는 것만으로 계정 변경·삭제 요청이 전송되어 계정 탈취가 가능함을 입증(보상금 $25,000, 패치 완료).
  - **근거**: 보안뉴스 등 보안 매체 보도(2019).
- **선정 사례 2 — 옥션(Auction) 관리자 세션 CSRF 악용 (2008년)**
  - **확인된 원인**: 내부 관리자가 메일 열람 시 유효한 관리자 세션 쿠키를 이용해 백그라운드로 권한 변경 요청이 전송된 CSRF 공격이 관리자 계정 탈취 경로 중 하나로 분석됨.
  - **근거**: 옥션 침해사고 분석 보도.

### 14. 비밀정보 유출과 외부 경계 관리 — `secrets-and-supply-chain`
- **슬라이드 설명 취약점**: 개발자 접속키 탈취, 소스코드 내 운영키 평문 하드코딩, 외부 위탁·백업 솔루션 등 확장된 경계 침해
- **선정 사례 1 — 티빙(TVING) 침해사고 (2026년 9월 조사 결과 발표)**
  - **확인된 원인**: 개발환경 접속키 탈취 후, 유출된 소스코드 프로젝트 361건 내부에 **평문 하드코딩된 운영환경 접속키 43개**와 암호화키까지 함께 노출되어 총 3,954만 개 계정 유출.
  - **근거**: 과학기술정보통신부·KISA 민관합동조사단 발표(2026-09-03), 전자신문·YTN 보도.
- **선정 사례 2 — PLAID KARTE 자격증명 반출 · JPMorgan/Visa/Mastercard 외부 업체 침해 · 더존비즈온 백업 침해 (2026년 10~11월)**
  - **확인된 원인**: 서버 취약점을 통한 DB 자격증명 탈취(KARTE), 위탁 서비스 업체 침해(JPMorgan 등), 백업 솔루션 취약점을 통한 백업 데이터 반출(더존비즈온).
  - **근거**: PLAID 공시(2026-11-16), AP(2026-11-19), 더존비즈온 공지(2026-10-23).

### 15. AI 시대의 경계: 간접 프롬프트 인젝션 — `prompt-injection-ai`
- **슬라이드 설명 취약점**: 외부 문서·이메일·댓글 등 비신뢰 데이터 속 숨은 지시를 AI 에이전트가 명령으로 오인해 내부 데이터를 유출하거나 도구를 오용하는 간접 프롬프트 인젝션
- **선정 사례 1 — Microsoft 365 Copilot "EchoLeak" (2025년, CVE-2025-32711)**
  - **확인된 원인**: 외부 이메일에 포함된 숨은 자연어 지시를 Copilot이 배경 처리 중 명령으로 해석하여 내부 SharePoint·OneDrive 데이터를 외부 서버로 유출할 수 있었던 최초의 실제 제로클릭 간접 프롬프트 인젝션(서버 측 패치 완료).
  - **근거**: NVD `CVE-2025-32711`, Aim Security 연구 보고.
- **선정 사례 2 — Comment and Control 연구 (2026년 4월) · Slack AI 간접 주입 연구**
  - **확인된 원인**: 이슈·PR 댓글 또는 공개 채널 메시지의 숨은 지시로 에이전트 권한을 악용한 자격증명·비공개 정보 유출 시연.
  - **근거**: `oddguan.com/blog/comment-and-control/` (2026-04), PromptArmor Slack AI 분석.
