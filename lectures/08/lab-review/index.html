맛집 테이블의 저장 규칙

열의 자료형·제약조건·기본값으로 행의 구조 정의

테이블 스키마 - 저장할 열과 허용할 값의 규칙
  • 행은 맛집 한 개 · 열은 이름·분류·평점 등의 속성
  • 기본 키는 행을 구별하는 값 · 중복과 NULL 금지
  • identity는 생략한 ID 생성 · BY DEFAULT는 명시한 ID도 허용
  • NOT NULL은 NULL 금지 · 빈 문자열 검사는 서버에서 별도 처리
  • DEFAULT는 생략한 열의 값 지정 · text[]는 메뉴 문자열 배열

supabase/schema.sql · 테이블 정의 전체

create table if not exists public.restaurants (
  id bigint generated by default as identity primary key,
  name text not null,
  category text not null,
  location text not null,
  price_range text not null default '정보 없음',
  rating numeric not null default 0,
  description text not null default '',
  recommended_menu text[] not null default '{}',
  likes integer not null default 0,
  image text not null default ''
);

새 맛집의 DB 등록

입력 확인 후 행을 저장하고 DB가 생성한 ID로 201 응답

등록 - 새 행을 저장한 뒤 저장 결과를 돌려주는 과정
  • 준비한 row를 insert에 전달해 새 행 저장 요청
  • DB의 identity가 입력에 없는 새 ID 생성
  • insert 뒤 select().single()로 저장된 한 행 수신
  • 저장 결과를 기존 Model로 변환한 뒤 Controller에서 201 응답

restaurants.service.ts · 등록 요청 발췌

const { data, error } = await getSupabase()
  .from('restaurants')
  .insert(row)
  .select(RESTAURANT_COLUMNS)
  .single();
if (error) throwDatabaseError(error);
const restaurant = Restaurant.fromDatabase(data!);

Controller · 저장 완료 후 응답 발췌

const restaurant =
  await restaurantService.createRestaurant(payload);
res.status(201).json({ data: restaurant });

접근 권한 - 요청 주체가 수행할 수 있는 작업의 범위
  • DB는 서버의 권한으로 처리 · API 호출자의 신원은 서버에서 별도 확인 필요

  • 화면의 버튼 비활성화만으로 HTTP 요청자의 작업 권한은 제한되지 않음
