챕터별 내용·선수 관계 검토

1장: 지능 과제→평가→공동 연구→기호·수치 접근의 관계 유지. 퍼셉트론에는 학습 최적화 수식 대신 입력·가중합·임곗값의 역할만 설명.
2장: 모델·학습·추론 뒤에 학습 신호의 유형을 배치. 학습 방식과 신경망 구조를 구분하고 역전파의 영향 계산과 실제 가중치 갱신을 분리. AlexNet·AlphaGo는 앞서 배운 구조·학습의 사례로 설명.
3장: 토큰 ID→벡터 표현→문맥 관련도→Transformer 순서 유지. 학습 병렬 계산과 순차 생성, 현재 문맥과 저장 기록, 유창함과 사실 근거를 각각 구분. 임의 벡터·연결선·생성 예시는 측정 결과로 표시하지 않음.
4장: 코드 제안에서 개발자가 수락·적용·실행하는 흐름을 설명. 지시 튜닝·선호 학습의 가중치 변경과 요청 시 퓨샷 예시 제공을 구분. 제목 함수는 문자열·trim·길이 1~20·boolean의 공통 조건 유지.
5장: 도구 요청→외부 실행→권한→에이전트 반복의 선수 관계 유지. 일반 모델 추론과 추론 모델을 구분하고 화면 해석과 실제 조작을 별도 설명. MCP에는 호스트 내부 클라이언트와 서버의 연결만 설명.
6장: 프로젝트 정보→정보 선별→공통 지침→재사용 절차→현재 기록→문맥 요약의 역할 구분. 코드의 현재 상태와 검증 근거를 다시 읽는 관계를 설명하며 스킬을 재학습이나 MCP로 설명하지 않음.
7장: 동작 명세→관찰 가능한 완료 기준→계획·작업 분해→함수·브라우저 검사→반복·Hooks·하네스→리뷰의 순서 유지. 개별 함수 검사와 저장·화면의 통합 검증을 구분. 실제 서비스가 없는 브라우저 발췌를 실행 완료로 주장하지 않음.
8장: 독립 범위와 연결 계약을 먼저 설명한 뒤 위임·협업·이력·작업 폴더·통합을 도입. 병렬화·목표 유지·중단 재개·예약 시작을 구분. 완료 보고보다 코드 차이와 실제 동작을 근거로 수용하도록 설명.

3페이지 · 1.1 · 인공지능
확정 문단: 인공지능은 인식·언어 이해·문제 해결처럼 인간의 지능과 관련된 과제를 기계로 수행하려는 연구 분야다. 이미 작성해 본 프로그램도 입력을 받아 결과를 만들지만, 지능적 과제에서는 표현이나 상황이 달라져도 적절한 판단을 내려야 한다. 예를 들어 정해진 숫자를 비교하는 일과 서로 다르게 쓰인 문의에서 같은 의도를 파악하는 일은 필요한 처리 방식이 다르며, 인공지능은 이러한 과제를 어떻게 표현하고 해결할지 다룬다.

발표용 본문:
지능적 과제 - 상황에 맞는 인식과 판단
  • 인식·언어 이해·문제 해결을 기계로 수행하려는 연구
  • 표현이나 상황이 달라져도 적절한 결과를 만드는 것이 목표
과제의 표현 - 입력과 판단 기준의 설정
  • 입력에서 무엇을 파악하고 어떤 결과를 만들지 정의
  • 숫자 비교와 문의 의도 파악은 서로 다른 처리 방식이 필요

자료 배치: wide

4페이지 · 1.2 · 튜링 테스트
확정 문단: 기계가 지능적 과제를 수행한다고 말하려면 무엇을 관찰해 평가할지 정해야 한다. 튜링은 1950년 기계가 생각하는지를 직접 정의하는 대신, 문자로 주고받는 대화에서 기계의 응답을 어떻게 판별할 수 있는지 묻는 모방 게임을 제시했다. 이를 통해 지능에 대한 추상적인 질문을 관찰 가능한 행동의 문제로 다룰 수 있지만, 사람처럼 대화했다는 사실만으로 의식이나 모든 과제의 해결 능력이 증명되는 것은 아니다.

발표용 본문:
모방 게임 - 문자 대화로 관찰하는 행동
  • 1950년 튜링이 제시한 기계 지능의 평가 관점
  • 상대의 정체를 가린 상태에서 질문과 응답으로 판별
평가 범위 - 관찰한 대화에서의 구별 가능성
  • 추상적인 지능의 질문을 관찰 가능한 행동으로 구체화
  • 사람 같은 응답만으로 의식이나 모든 과제의 능력을 증명할 수 없음

자료 배치: wide

5페이지 · 1.3 · 다트머스 연구 모임
확정 문단: 기계 지능을 평가하는 질문은 지능을 실제로 구현할 수 있는지 탐구하는 공동 연구로 이어졌다. 1955년에 제안되고 1956년에 열린 다트머스 연구 모임은 학습과 지능의 여러 특징을 기계로 모사할 수 있다는 연구 목표를 공유했다. 이 모임은 인공지능이라는 분야를 정립한 중요한 출발점이며, 하나의 완성된 기술을 발표한 사건이라기보다 여러 구현 접근이 발전할 연구 의제를 마련한 사건이다.

발표용 본문:
공동 연구 의제 - 지능을 기계로 구현하는 목표
  • 학습과 지능의 특징을 기계로 모사할 가능성 탐구
  • 여러 구현 접근을 함께 연구할 분야의 출발점 마련
제안과 모임 - 구분되는 두 시점
  • 1955년 연구 제안서를 바탕으로 1956년 여름 모임 개최
  • 완성 기술의 공개보다 연구 목표와 문제의 공유에 의미

자료 배치: side

6페이지 · 1.4 · 기호 기반 인공지능
확정 문단: 지능을 구현하는 초기 접근 중 하나는 대상과 관계를 기호로 나타내고 명시적인 규칙을 적용하는 방식이었다. 기호 기반 인공지능에서는 알려진 사실을 지식으로 저장하고, 조건에 맞는 규칙을 적용해 새로운 결론을 얻는다. 예를 들어 어떤 물체가 특정 조건을 만족한다는 사실과 분류 규칙을 함께 사용하면 그 물체의 범주를 판단할 수 있으며, 어떤 규칙이 결론에 사용됐는지 추적할 수 있다.

발표용 본문:
기호 표현 - 대상과 관계를 명시한 지식
  • 알려진 사실을 기계가 다룰 수 있는 기호로 표현
  • 조건과 결론의 관계를 사람이 규칙으로 작성
규칙 적용 - 사실에서 결론을 얻는 과정
  • 현재 사실에 맞는 규칙을 찾아 새로운 결론 도출
  • 판단에 사용한 사실과 규칙을 따라 결과 추적 가능

자료 배치: wide

7페이지 · 1.5 · 퍼셉트론
확정 문단: 명시적인 규칙을 조합하는 접근과 함께 입력을 수치로 처리하는 초기 모형도 연구됐다. 퍼셉트론은 각 입력에 가중치를 곱해 더한 값과 임곗값을 비교해 결과를 결정하며, 가중치는 입력이 판단에 미치는 영향의 크기를 나타낸다. 입력 두 개를 사용하는 분류 문제에서는 가중치와 임곗값에 따라 두 결과를 가르는 기준이 달라지고, 단일 퍼셉트론이 표현할 수 있는 판단에는 한계가 있다.

발표용 본문:
가중합 - 입력의 영향을 합친 값
  • 각 입력에 가중치를 곱한 뒤 그 결과를 합산
  • 가중치는 해당 입력이 판단에 미치는 영향의 크기
임곗값 판단 - 두 결과를 가르는 기준
  • 가중합이 기준 이상인지 비교해 출력 결정
  • 가중치·임곗값에 따라 판단 기준이 달라지며 표현 범위에는 한계

자료 배치: wide

8페이지 · 1.6 · 전문가 시스템
확정 문단: 수치 기반 모형과 병행하던 기호·규칙 계열에서는 전문가의 판단을 특정 분야에 적용하는 전문가 시스템이 발전했다. 전문가 시스템은 분야의 사실과 규칙을 보관한 지식 기반, 그리고 현재 정보에 적용할 규칙을 찾아 결론을 도출하는 추론 부분으로 구성된다. 장비의 증상을 입력하면 점검 규칙에 따라 고장 원인 후보를 제시할 수 있지만, 새로운 증상과 예외를 다루려면 지식을 추가하고 규칙 사이의 일관성을 관리해야 한다.

발표용 본문:
지식 기반 - 특정 분야의 사실과 규칙
  • 전문가의 판단에 쓰이는 지식을 명시적으로 보관
  • 새로운 증상과 예외를 다루려면 지식과 규칙의 갱신 필요
추론 엔진 - 현재 정보에 적용할 규칙의 선택
  • 입력한 증상과 규칙을 연결해 고장 원인 후보 도출
  • 규칙이 늘어나면 서로 모순되지 않도록 일관성 관리 필요

자료 배치: wide

10페이지 · 2.1 · AI 겨울
확정 문단: 전문가 시스템을 비롯한 초기 접근은 제한된 문제에서 성과를 보였지만, 실제 환경의 복잡성과 지식 관리 비용을 충분히 감당하지 못하는 경우도 있었다. AI 겨울은 이러한 기술적 한계와 높은 기대 사이의 차이가 연구비와 관심의 위축으로 이어진 시기를 가리킨다. 1970년대와 1980년대 후반 이후의 위축은 배경이 서로 달랐으며, 이를 하나의 모델 실패나 연구 전체의 중단으로 이해해서는 안 된다.

발표용 본문:
기대와 성과의 차이 - 지원 위축의 배경
  • 제한된 문제의 성과를 복잡한 현실로 확장하는 데 어려움
  • 기술적 한계와 높은 기대의 차이가 투자·관심 감소로 연결
복수의 위축 시기 - 서로 다른 원인과 조건
  • 1970년대와 1980년대 후반 이후의 위축을 구분
  • 하나의 모델 실패나 인공지능 연구 전체의 중단을 뜻하지 않음

자료 배치: wide

11페이지 · 2.2 · 머신러닝
확정 문단: 판단 규칙을 사람이 모두 작성하는 부담을 줄이는 한 방법은 데이터를 이용해 판단 기준을 얻는 것이다. 머신러닝에서 모델은 입력을 결과로 바꾸는 계산 구조이며, 학습 과정은 데이터와 목표에 맞춰 그 구조의 내부 값을 조정한다. 예를 들어 메시지를 분류할 때 사람이 모든 표현의 규칙을 나열하는 대신 여러 메시지 사례에서 기준을 얻을 수 있으며, 이러한 접근은 초기 인공지능 연구부터 병행되어 이후 데이터와 계산 자원의 확대와 함께 발전했다.

발표용 본문:
모델 - 입력을 결과로 바꾸는 계산 구조
  • 내부 값에 따라 같은 입력의 처리 결과가 달라지는 구조
  • 사람이 모든 경우의 판단 규칙을 직접 쓰는 부담 감소
데이터 기반 학습 - 사례에서 판단 기준 획득
  • 데이터와 학습 목표에 맞춰 모델의 내부 값 조정
  • 초기 AI 연구부터 병행한 접근이 데이터·계산 자원과 함께 발전

자료 배치: wide

12페이지 · 2.3 · 모델의 학습
확정 문단: 모델의 학습은 같은 입력에서 더 적절한 결과가 나오도록 가중치 같은 내부 값을 조정하는 과정이다. 모델이 현재 값으로 결과를 계산하면 학습 목표를 기준으로 그 결과를 평가하고, 개선에 도움이 되는 방향으로 값을 바꾸는 일을 반복한다. 퍼셉트론에서 가중치가 달라지면 판단 기준이 달라지는 것처럼 학습은 모델의 처리 방식을 바꾸지만, 학습에 사용한 사례를 잘 처리했다는 사실만으로 새로운 입력에서도 항상 정확하다고 보장할 수는 없다.

발표용 본문:
학습 목표 - 결과를 평가하는 기준
  • 현재 모델의 출력이 목표에 얼마나 맞는지 평가
  • 평가 결과를 내부 값의 개선 방향을 정하는 데 사용
반복 조정 - 모델의 처리 방식 변화
  • 예측·평가·조정을 반복해 가중치 등 갱신
  • 학습 사례의 성과와 새로운 입력의 정확성은 별도로 확인

자료 배치: wide

13페이지 · 2.4 · 모델의 추론
확정 문단: 학습이 모델의 내부 값을 조정하는 단계라면 추론은 학습된 모델에 입력을 넣어 결과를 계산하는 단계다. 학습을 마친 메시지 분류기에 처음 보는 메시지를 넣으면, 모델은 이미 얻은 판단 기준을 사용해 분류 결과를 만든다. 일반적인 추론에서는 입력이 달라져 출력이 달라지더라도 그 요청만으로 모델의 가중치가 다시 학습되는 것은 아니므로, 입력의 변화와 모델 자체의 변화를 구분해야 한다.

추론 - 학습한 기준으로 새 결과 계산

78페이지 · 8.3 · 에이전트 팀
확정 문단: 한 작업의 결과를 받아오는 위임에서 더 나아가 여러 에이전트의 진행을 함께 조정할 수도 있다. 에이전트 팀은 역할과 작업 상태를 공유하고 필요한 정보를 교환하며 여러 작업을 협업하는 구조로, 조정 역할은 중복 작업과 누락을 확인하고 결과를 모은다. 화면·서버·검증 역할을 나눌 수 있지만 각 에이전트가 같은 지식과 상태를 자동으로 공유한다고 가정해서는 안 되며, 협업 구조를 제공하는 제품의 지원 범위도 구분해야 한다.

발표용 본문:
협업 구조 - 역할과 진행을 조정하는 여러 에이전트

공유의 조건 - 명시적인 정보 전달과 지원 범위
  • 별도 에이전트의 지식과 상태가 자동으로 같아지지는 않음

79페이지 · 8.4 · Git 브랜치
확정 문단: 여러 에이전트가 코드 변경을 만들면 각 변경이 어떤 기준에서 시작했는지와 어떤 이력을 갖는지 구분해야 한다. Git은 변경 상태를 커밋이라는 기록으로 남기고, 브랜치는 이러한 기록을 서로 다른 흐름으로 이어갈 수 있게 하는 이름 있는 기준이다. 같은 상태에서 시작한 화면 변경과 서버 변경을 별도 브랜치에 기록하면 결과를 나누어 검토할 수 있지만, 브랜치만 만들었다고 각 작업자가 편집할 별도 디렉터리가 자동으로 생기는 것은 아니다.

발표용 본문:
커밋 - 변경 상태를 남기는 이력 단위
  • 공통 상태를 기준으로 각각의 변경 결과 기록
  • 같은 기준에서 어떤 결과로 달라졌는지 비교 가능
브랜치 - 커밋 이력을 가리키는 이름
  • 화면 변경과 서버 변경을 서로 다른 흐름으로 기록
  • 브랜치 생성만으로 별도 작업 디렉터리가 생기지는 않음

80페이지 · 8.5 · Git worktree
확정 문단: 브랜치로 변경 이력을 나눈 뒤 서로 다른 변경을 실제로 동시에 편집하려면 작업 파일을 다룰 공간도 구분해야 한다. Git worktree는 하나의 저장소에 연결된 작업 디렉터리를 추가해, 서로 다른 브랜치의 파일을 각 디렉터리에서 다룰 수 있게 한다. 화면과 서버를 맡은 에이전트에게 각 작업 공간을 줄 수 있지만, 파일 공간의 분리가 외부 데이터베이스나 실행 중인 서버까지 자동으로 분리해 주는 것은 아니므로 공유하는 자원도 확인해야 한다.

발표용 본문:
작업 디렉터리의 추가 - 브랜치별 파일 공간
  • 하나의 저장소에 연결된 작업 디렉터리를 추가
  • 서로 다른 브랜치의 파일을 각 공간에서 편집
공유 자원의 확인 - 파일 공간 밖의 의존성
  • 에이전트별 파일 변경을 분리해 동시 편집의 충돌 감소
  • DB·포트·외부 서비스는 자동 분리되지 않으므로 별도 확인

발표용 본문:
변경 결합 - 충돌 해결과 연결 관계 확인

  • 요청·응답의 형식이 합의한 계약과 맞는지 확인
통합 검증 - 결합한 상태에서의 동작 확인
  • 개별 작업의 통과 결과가 전체 동작을 보장하지는 않음
