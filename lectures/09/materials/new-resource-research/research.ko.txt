9주차 · 나머지 60개 슬라이드의 새 자료 조사
확인일: 2026-11-07

설계 번호는 챕터.항목, 화면 번호는 표지·챕터 표지를 포함한 실제 강의 번호.
배치 전의 권장 자료와 제작 조건을 보존한 기록. 현재 반영 상태·페이지별 레퍼런스는 상위 폴더의 resource-placements.json과 slide-references.html 참고.

조사 범위와 제작 방향

- 조사 당시 본문 76장 중 기존 자료가 있는 16장을 유지하고 제목·부제만 있던 60장에 새 후보를 대응. 챕터 표지 8장과 주차 표지는 조사 대상에서 제외.
- 이 문서는 배치 전 조사·설계를 보존한 기록. 이후 실제 반영 상태와 선택·수정한 범위는 resource-placements.json과 slide-references.html에서 관리.
- 원문에 있는 그림 / 원리만 참고한 재작성 도식 / 직접 만든 교육용 사례 / 실제 실행한 출력 / 아직 필요한 캡처를 구분.
- 기본은 네이티브 HTML/SVG·표·짧은 코드. 생성형 장식 이미지나 모든 슬라이드의 제품 스크린샷은 준비하지 않음.
- 가장 먼저 제목 함수·메시지 자료·텍스트 처리·에이전트 반복·프로젝트 파일 지도를 만들고 후속 슬라이드에서 같은 요소를 확장. 슬라이드마다 다른 완성 앱을 도입하지 않음.
- 공통 함수는 문자열 입력·앞뒤 공백 제거·길이 1~20·boolean 결과. JS length는 UTF-16 단위이므로 예제는 ASCII/완성형 한글로 제한. 모든 Unicode 글자 수 처리는 별도 요구 정의 없이는 주장하지 않음.
- 타임라인은 기술의 발명 연도를 모두 의미하지 않음. Git·명세·테스트 등은 오래된 기법을 최근 에이전트 개발에 적용하는 맥락.
- 새 도식 라벨은 본문 반영 시 KO/EN 쌍으로 작성. 최신 사용자 지시에 따라 출처는 별도 레퍼런스 문서에서만 관리. 한글 비트맵 문구를 영문 화면에 그대로 두지 않음.
- 외부 그림의 접근 가능 여부와 재배포 조건은 별개. 원본 이미지를 실제 저장·공개하는 단계에서는 선택한 원본의 출처·표시 조건을 기록. 이번에는 출처 링크와 활용 범위만 확정.

[1.1 / 화면 3] 인공지능
학습 초점: 인간의 지능적 과제를 기계로 수행하려는 연구 분야
확정 문단: 인공지능은 인식·언어 이해·문제 해결처럼 인간의 지능과 관련된 과제를 기계로 수행하려는 연구 분야다. 이미 작성해 본 프로그램도 입력을 받아 결과를 만들지만, 지능적 과제에서는 표현이나 상황이 달라져도 적절한 판단을 내려야 한다. 예를 들어 정해진 숫자를 비교하는 일과 서로 다르게 쓰인 문의에서 같은 의도를 파악하는 일은 필요한 처리 방식이 다르며, 인공지능은 이러한 과제를 어떻게 표현하고 해결할지 다룬다.
권장 자료: 고정된 수 비교와 표현이 다른 문의의 두 열 비교 (비교)
구성·활용: 왼쪽: 10 > 5 → true. 오른쪽: 「배송은 언제 오나요?」「택배 도착일을 알려주세요」→ 같은 배송 시점 문의. 오른쪽은 해결할 과제의 예시로만 표시.
흐름 연결: 프로그래밍 경험에서 지능적 과제의 범위로 출발. 다음 1.2에서 수행을 어떻게 평가할지 질문을 좁힘.
선수 관계: 강의 출발
선행 설명·오해 방지: LLM·학습 데이터·토큰·AI/ML/DL 포함 관계를 아직 넣지 않음. 규칙 프로그램이 AI가 될 수 없다는 이분법도 피함.

[1.3 / 화면 5] 다트머스 연구 모임

[1.4 / 화면 6] 기호 기반 인공지능
학습 초점: 지식을 기호와 규칙으로 표현해 결론을 도출하는 접근
확정 문단: 지능을 구현하는 초기 접근 중 하나는 대상과 관계를 기호로 나타내고 명시적인 규칙을 적용하는 방식이었다. 기호 기반 인공지능에서는 알려진 사실을 지식으로 저장하고, 조건에 맞는 규칙을 적용해 새로운 결론을 얻는다. 예를 들어 어떤 물체가 특정 조건을 만족한다는 사실과 분류 규칙을 함께 사용하면 그 물체의 범주를 판단할 수 있으며, 어떤 규칙이 결론에 사용됐는지 추적할 수 있다.
권장 자료: 사실 카드 → 규칙 적용 → 새 결론의 추론 경로 (도식)
구성·활용: 설명용 분류 체계: 사실 「A는 변 3개를 가진 닫힌 평면 도형」 + 규칙 「변 3개인 다각형은 삼각형」 → 결론 「A는 삼각형」. 사용한 규칙에 같은 색 표시.
흐름 연결: 연구 의제에서 명시적 지식 표현으로 이동. 1.5에서는 규칙 대신 수치 계산을 쓰는 병행 접근을 대비.
선수 관계: dartmouth
선행 설명·오해 방지: 전문가 시스템 전체 구조·학습·역전파를 이 도식에 포함하지 않음.

[2.2 / 화면 11] 머신러닝
학습 초점: 데이터에서 과제 수행에 필요한 판단 기준을 얻는 방법
확정 문단: 판단 규칙을 사람이 모두 작성하는 부담을 줄이는 한 방법은 데이터를 이용해 판단 기준을 얻는 것이다. 머신러닝에서 모델은 입력을 결과로 바꾸는 계산 구조이며, 학습 과정은 데이터와 목표에 맞춰 그 구조의 내부 값을 조정한다. 예를 들어 메시지를 분류할 때 사람이 모든 표현의 규칙을 나열하는 대신 여러 메시지 사례에서 기준을 얻을 수 있으며, 이러한 접근은 초기 인공지능 연구부터 병행되어 이후 데이터와 계산 자원의 확대와 함께 발전했다.
권장 자료: 사람이 정한 규칙과 데이터로 얻은 판단 기준의 입력 비교 (비교)
구성·활용: 같은 문의/광고 메시지 카드 사용. 왼쪽은 사람이 작성한 분류 조건 → 프로그램, 오른쪽은 분류 사례 → 학습 → 모델. 예측값은 실험 결과가 아닌 설명용 사례.
흐름 연결: 2.1의 규칙 관리 한계에서 판단 기준을 얻는 방식으로 이동. 2.3에서 학습 상자 내부를 확대.
선수 관계: ai-winter, expert-system
선행 설명·오해 방지: 분류 사례를 제시하되 지도학습이라는 유형 이름·신경망 구조를 먼저 정의하지 않음.

[2.3 / 화면 12] 모델의 학습
학습 초점: 학습 목표에 따라 모델의 내부 값을 조정하는 과정
확정 문단: 모델의 학습은 같은 입력에서 더 적절한 결과가 나오도록 가중치 같은 내부 값을 조정하는 과정이다. 모델이 현재 값으로 결과를 계산하면 학습 목표를 기준으로 그 결과를 평가하고, 개선에 도움이 되는 방향으로 값을 바꾸는 일을 반복한다. 퍼셉트론에서 가중치가 달라지면 판단 기준이 달라지는 것처럼 학습은 모델의 처리 방식을 바꾸지만, 학습에 사용한 사례를 잘 처리했다는 사실만으로 새로운 입력에서도 항상 정확하다고 보장할 수는 없다.
권장 자료: 예측 → 정답과 비교 → 내부 값 조정의 순환 (도식)
구성·활용: 광고 메시지 1개를 넣어 처음의 오분류와 비교 결과를 보여 주고 모델 내부 수치가 바뀌는 화살표 표시. 연습 데이터와 아직 보지 않은 데이터를 구분.
흐름 연결: 2.2의 학습 상자를 확대. 2.4에서는 동일 모델을 고정해 새 입력을 처리.
선수 관계: machine-learning, perceptron
선행 설명·오해 방지: 정확도가 매번 단조 증가한다는 가짜 그래프·역전파 수식·구체 학습률 제외.

[2.4 / 화면 13] 모델의 추론
학습 초점: 학습한 모델에 새 입력을 넣어 결과를 얻는 과정
확정 문단: 학습이 모델의 내부 값을 조정하는 단계라면 추론은 학습된 모델에 입력을 넣어 결과를 계산하는 단계다. 학습을 마친 메시지 분류기에 처음 보는 메시지를 넣으면, 모델은 이미 얻은 판단 기준을 사용해 분류 결과를 만든다. 일반적인 추론에서는 입력이 달라져 출력이 달라지더라도 그 요청만으로 모델의 가중치가 다시 학습되는 것은 아니므로, 입력의 변화와 모델 자체의 변화를 구분해야 한다.
권장 자료: 학습된 모델 고정 → 새 메시지 → 분류 결과 (도식)
구성·활용: 2.3과 같은 모델 모양에 「학습된 값 고정」 표시. 새 메시지 한 장만 통과시키며 갱신 화살표는 없음.
흐름 연결: 방금 본 학습과 입력 처리 시점의 차이를 시각적으로 비교. 이후 학습 유형의 차이를 살필 기준 제공.
선수 관계: training
선행 설명·오해 방지: 추론(inference)을 5.6의 추론 모델(reasoning model)과 같은 뜻으로 설명하지 않음.

[2.5 / 화면 14] 지도학습
학습 초점: 입력과 정답의 대응 관계를 학습하는 방식
확정 문단: 학습과 추론의 관계를 이해했다면, 학습 중 어떤 정보를 제공하는지에 따라 학습 방식을 나눠 볼 수 있다. 지도학습은 입력과 그 입력에 대응하는 정답을 함께 제공하고, 모델의 예측이 정답에 가까워지도록 학습하는 방식이다. 스팸 여부가 표시된 메시지로 학습한 뒤 새로운 메시지를 분류하는 사례에서, 정답 표시는 학습 기준을 제공하고 새 메시지의 분류는 추론에 해당한다.
권장 자료: 메시지와 정답 열이 있는 학습 자료 표 (표)
구성·활용: 「무료 쿠폰을 받으세요」/광고, 「내일 회의는 2시입니다」/일반 등 창작 예시 4행. 표 아래 새 메시지는 정답 칸을 비우고 모델 결과로 채움.
흐름 연결: 2.3의 비교 기준이 어디서 왔는지 명시. 2.6에서는 정답 열을 제거해 차이를 보임.
선수 관계: training, inference
선행 설명·오해 방지: 표 4행으로 충분한 실제 모델을 학습했다고 주장하지 않음. 성능 숫자·실제 이메일 개인정보 제외.
준비 상태: 설계·출처 확인; 제작/캡처 후 검증 필요

[2.6 / 화면 15] 비지도학습
학습 초점: 정답 표시 없이 데이터의 구조와 유사성을 찾는 방식
확정 문단: 지도학습과 달리 비지도학습은 각 입력의 정답을 지정하지 않은 데이터에서 구조나 반복되는 패턴을 찾는다. 모델은 데이터 사이의 유사성이나 분포를 이용해 묶음과 표현을 만들며, 사람이 미리 붙인 분류 이름을 그대로 맞추는 것이 목표는 아니다. 예를 들어 이름표가 없는 고객 문의를 비슷한 내용끼리 묶을 수 있지만, 만들어진 묶음에 어떤 의미가 있는지는 별도로 확인해야 한다.
권장 자료: 정답 없는 문의 카드 → 유사한 묶음 → 사람의 해석 (도식)
구성·활용: 배송 문의 2개·결제 문의 2개·계정 문의 2개의 창작 카드. 알고리즘 결과를 가정한 그룹 A/B/C에 모은 뒤 점선으로 「사람이 붙인 의미」 표시.
흐름 연결: 2.5의 정답 열 유무를 대비하고 2.7에서 행동 후 보상이라는 다른 피드백 도입.
선수 관계: supervised-learning
선행 설명·오해 방지: 그룹 이름이 학습 때 제공된 정답처럼 보이지 않게 함. 임베딩 좌표·클러스터 알고리즘 수학은 제외.
준비 상태: 설계·출처 확인; 제작/캡처 후 검증 필요

[2.7 / 화면 16] 강화학습
학습 초점: 행동의 결과로 얻는 보상을 바탕으로 행동 방식을 개선하는 과정
확정 문단: 정답이 있는 사례나 데이터의 구조를 이용하는 방식에 더해, 행동의 결과를 통해 배우는 강화학습도 있다. 강화학습의 주체는 환경에서 행동을 선택하고 그 결과로 상태의 변화와 보상을 받은 뒤, 장기적으로 더 좋은 보상을 얻도록 행동 방식을 개선한다. 격자에서 목표 지점까지 이동하는 사례에서는 각 위치의 정답 행동을 모두 제공하지 않아도 보상을 통해 이동 방식을 배울 수 있으며, 지금 얻는 보상과 이후의 결과를 함께 고려해야 한다.
권장 자료: 격자 이동 사례를 붙인 에이전트–환경 순환 (도식)
구성·활용: 에이전트 → 이동 행동 → 격자 환경 → 새 위치와 보상 → 에이전트. 도착 +1·벽 이동 0 같은 보상 규칙은 「설명용 설계」로 표시.
흐름 연결: 데이터의 정답 대신 행동 결과를 활용하는 학습을 설명. 2.12 AlphaGo의 자기 대국과 연결.
선수 관계: training, supervised-learning, unsupervised-learning
선행 설명·오해 방지: 최적 경로를 실제로 학습한 결과처럼 표시하지 않음. 5장의 도구 사용 에이전트와 보상 학습을 동일시하지 않음.
준비 상태: 설계·출처 확인; 제작/캡처 후 검증 필요

  https://developers.google.com/machine-learning/intro-to-ml/what-is-ml

[2.9 / 화면 18] 역전파
학습 초점: 출력 오차에 대한 각 가중치의 영향을 계산하는 방법

권장 자료: 기존 2.8 신경망 위의 순방향 계산·역방향 영향 계산 (도식)

[3.1 / 화면 23] 언어 모델

[3.3 / 화면 25] 임베딩

[3.4 / 화면 26] 어텐션
학습 초점: 문맥에 필요한 다른 위치의 정보를 선택적으로 반영하는 계산
확정 문단: 토큰을 각각 수치로 표현한 것만으로는 문장 안에서 어떤 표현들이 서로 관련되는지 충분히 반영할 수 없다. 어텐션은 현재 위치의 표현과 다른 위치의 표현 사이에서 관련도를 계산하고, 그 정도에 따라 다른 위치의 정보를 가중해 반영하는 방식이다. 문장 속 지시어를 해석할 때 앞에 나온 대상의 정보가 필요한 상황처럼, 같은 토큰도 주변 정보가 반영되면 문맥에 따른 표현으로 바뀔 수 있다.
권장 자료: 문장 속 표현의 관련성을 강조하는 연결선 (도식)

흐름 연결: 3.3의 수치 표현들을 문맥에 따라 함께 참조함을 설명. 3.5 기존 Transformer 도식의 attention 상자로 연결.
선수 관계: embeddings, language-model
선행 설명·오해 방지: 문법적 관계 하나가 모델 내부 사고의 증거라고 쓰지 않음. Q/K/V 행렬·softmax 식은 넣지 않음.
준비 상태: 설계·출처 확인; 제작/캡처 후 검증 필요

[3.6 / 화면 28] 자기지도학습
학습 초점: 데이터 자체에서 예측 목표를 만들어 학습하는 방식
확정 문단: 텍스트를 처리할 모델 구조가 있어도 이를 학습시키려면 각 입력에서 무엇을 맞힐지 정해야 한다. 자기지도학습은 데이터 자체에서 예측 목표를 만들어 사용하는 방식으로, 문장의 일부를 가리고 그 내용을 맞히거나 앞부분에서 뒤에 이어질 내용을 예측하게 할 수 있다. 모든 문장에 사람이 별도의 분류 이름을 붙이지 않아도 대량의 텍스트에서 학습 사례를 만들 수 있지만, 사용하는 데이터와 목표에 따라 얻는 능력도 달라진다.
권장 자료: 원문에서 입력과 학습 목표를 만드는 두 예시 (도식)
구성·활용: 「오늘은 비가 온다」의 일부 가리기 → 가린 표현, 앞부분만 제공 → 이어질 표현. 각 행에서 목표도 원문에서 얻었다는 화살표 강조.

[3.7 / 화면 29] 사전 학습
학습 초점: 개별 과제에 적용하기 전에 폭넓은 데이터로 기본 능력을 학습하는 단계
확정 문단: 자기지도학습이 학습 목표를 얻는 방식이라면, 사전 학습은 개별 과제에 적용하기 전에 폭넓은 데이터로 기본 능력을 익히는 단계다. 언어 모델은 대량의 텍스트에 이러한 학습을 적용해 표현의 관계와 반복되는 패턴을 내부 가중치에 반영할 수 있다. 이 단계에서 얻은 모델은 여러 과제에 활용할 기반이 되지만, 문서를 원문 그대로 보관하는 저장소가 되거나 모든 사용자 요청을 적절히 수행하는 상태가 자동으로 완성되는 것은 아니다.
권장 자료: 다양한 문서 → 자기지도 과제 → 반복 학습 → 기본 모델 (도식)
구성·활용: 직접 작성한 짧은 설명문·대화문·문서 조각 3종을 3.6의 입력/목표 생성 상자에 넣음. 모델 내부 값이 갱신되는 화살표 사용.
흐름 연결: 3.6의 과제를 큰 자료에 적용하는 학습 단계로 확장. 3.8에서 규모와 모델의 종류를 비교.
선수 관계: self-supervision, transformer
선행 설명·오해 방지: 문서를 그대로 저장한 검색 창고처럼 표현하지 않음. 지시 튜닝·선호 학습은 4장까지 보류.
준비 상태: 설계·출처 확인; 제작/캡처 후 검증 필요

[3.8 / 화면 30] 대규모 언어 모델
학습 초점: 대규모 학습을 통해 여러 언어 과제에 활용되는 모델
확정 문단: 언어 모델의 구조와 사전 학습을 큰 규모의 데이터와 계산으로 확장한 것이 대규모 언어 모델이다. 모델은 학습된 언어 표현을 여러 과제에 활용할 수 있어 문장 완성뿐 아니라 요약과 질문 응답 같은 작업에도 적용된다. BERT와 GPT 계열은 사전 학습 언어 모델의 발전을 보여주는 사례지만 모델마다 학습 목표와 활용 방식이 다르며, 언어 모델 자체와 그 모델을 이용해 만든 대화 서비스도 구분해야 한다.
권장 자료: BERT와 GPT 계열의 학습 목표·주요 사용 방식 비교 (비교)
구성·활용: BERT: 가린 표현의 문맥적 예측 / GPT 계열: 앞 문맥에서 다음 표현 예측. 별도 작은 구조로 모델 → 대화 UI를 붙인 서비스 구분. 세부 파라미터 경쟁 그래프는 생략.

선수 관계: pretraining, language-model, transformer
선행 설명·오해 방지: BERT를 ChatGPT와 동일한 대화 서비스로 묘사하지 않음. 현재 모델의 규모·성능을 추정하지 않음.

선수 관계: text-generation, tokens

[3.11 / 화면 33] 언어 모델의 환각

확정 문단: 답변에 필요한 근거가 부족하다면 관련 자료를 찾아 현재 입력에 추가하는 방법을 사용할 수 있다. 검색 증강 생성은 질문과 관련된 문서를 검색한 뒤 그 내용을 언어 모델에 제공해 답변을 만들게 하는 방식이며, 모델 가중치를 다시 학습하지 않고도 외부 자료를 활용할 수 있다. 수업 안내 문서에서 해당 내용을 찾아 질문과 함께 전달하는 사례에서는 답의 근거를 확인하기 쉬워지지만, 검색이 잘못되거나 제공된 자료를 잘못 해석하면 오류가 남을 수 있다.

[4.1 / 화면 36] 코드 생성 모델

[4.2 / 화면 37] 코드 자동 완성

[4.4 / 화면 39] 사람의 피드백을 통한 학습
학습 초점: 사람의 평가와 선호를 반영해 응답 방식을 조정하는 과정
확정 문단: 요청에 맞는 응답 예시를 학습한 뒤에는 여러 응답 중 사람이 어느 것을 더 적절하게 보는지도 반영할 수 있다. 사람의 피드백을 통한 학습은 응답에 대한 평가나 선호 데이터를 이용해 모델의 응답 방식을 조정하는 과정이며, 강화학습을 사용하는 방식도 있고 다른 학습 방식도 있다. 같은 코드 설명이라도 더 정확하고 이해하기 쉬운 응답을 선호하도록 조정할 수 있지만, 학습에서 선호를 반영했다는 사실이 모든 응답의 정확성을 보장하지는 않는다.
권장 자료: 같은 요청의 답변 A/B → 사람의 비교 → 학습 신호 (도식)
구성·활용: 짧고 정확한 답과 요구를 놓친 답의 창작 카드. 사람의 비교 결과가 학습 절차로 전달되는 연결. 강화학습 적용은 이미 배운 보상 개념 수준의 보조 표시.
흐름 연결: 4.3의 시범 답안과 선호 비교 데이터의 차이를 보여 준 뒤 실제 대화형 개발로 이동.
선수 관계: instruction-tuning, training, reinforcement-learning
선행 설명·오해 방지: 현재 사용자의 좋아요 클릭이 즉시 해당 모델 가중치를 갱신한다고 쓰지 않음. 모든 최신 모델이 동일 RLHF 구현이라는 주장 제외.
준비 상태: 설계·출처 확인; 제작/캡처 후 검증 필요

[4.5 / 화면 40] 대화형 개발 지원
학습 초점: 자연어 대화로 코드의 작성과 설명을 요청하는 방식
확정 문단: 코드 생성 능력에 지시 수행과 적절한 응답 방식이 결합되면 개발자는 자연어 대화로 작업을 요청할 수 있다. 대화형 개발 지원에서는 함수 작성, 기존 코드의 설명, 오류 원인의 검토를 요청하고 추가 조건을 전달하며 결과를 다듬는다. 여기서 다루는 기본 대화 방식은 개발자가 코드를 프로젝트에 반영하고 실행 결과를 다시 전달하는 형태로, 대화가 이어지는 것만으로 파일 변경이나 명령 실행까지 자동으로 일어나는 것은 아니다.
권장 자료: 사람과 대화 모델 사이의 수정 요청 왕복 (도식)

선수 관계: human-feedback, code-model, context-window
선행 설명·오해 방지: 자동 파일 수정·도구 호출·자동 테스트 러너를 대화 모델의 기본 기능처럼 그리지 않음.

[5.2 / 화면 47] 도구 실행 권한

확정 문단: 도구 호출이 실제 환경의 읽기와 변경으로 이어지면, 실행할 수 있는 범위를 정하는 일이 필요하다. 도구 실행 권한은 접근 가능한 파일과 외부 자원, 허용되는 변경을 제한하는 기준이며, 실행 프로그램과 환경의 제한을 통해 적용된다. 프로젝트 파일을 읽는 권한과 수정하는 권한, 외부로 데이터를 보내는 권한은 구분할 수 있으므로, 모델이 도구를 요청했다는 이유만으로 모든 행동을 허용해서는 안 된다.

[5.3 / 화면 48] AI 에이전트의 작업 반복
학습 초점: 목표에 따라 도구를 선택하고 결과를 관찰하며 다음 행동을 결정하는 구조
확정 문단: 허용된 도구의 실행 결과를 다시 입력으로 사용하면 모델은 한 번의 응답 이후에도 작업을 이어갈 수 있다. AI 에이전트의 작업 반복은 목표를 바탕으로 행동을 선택하고, 도구가 반환한 결과를 관찰한 뒤 다음 행동이나 종료를 결정하는 구조다. 파일을 읽은 결과에 따라 수정하거나 추가 정보를 찾는 것처럼 실제 관찰이 다음 선택의 근거가 되며, 이러한 실행 반복 자체가 모델의 가중치를 학습하는 과정은 아니다.
권장 자료: 목표 → 행동 선택 → 도구 결과 관찰 → 다음 행동/종료 (도식)

흐름 연결: 한 번의 호출에서 결과를 근거로 다음 행동을 선택하는 에이전트로 확장.
선수 관계: tool-calling, tool-permissions, context-window
선행 설명·오해 방지: 반복을 모델 가중치 학습으로 표시하지 않음. 테스트·Hooks·장기 목표 기능의 내부 구조를 미리 넣지 않음.

권장 자료: 입력 → 응답 전 계산 → 답변/행동의 과정 띠 (비교)
구성·활용: 짧은 계산과 더 많은 추론 계산의 개략 폭 비교. 수행 시간·계산량 증가와 문제 해결의 관계를 정성적으로 표현.
흐름 연결: 5.5의 실행 결과를 어떻게 검토하고 다음 행동을 정하는지에서 모델 계산 방식으로 시점을 전환.

[5.9 / 화면 54] Model Context Protocol

확정 문단: Hook이 특정 사건에 동작을 연결한다면 실행 하네스는 작업을 진행할 전체 실행 구조를 구성한다. 하네스는 모델과 도구, 실행 환경, 진행 상태, 검사 결과를 연결하고 다음 작업의 시작과 종료, 실패 후 처리와 실행 한도 등을 관리한다. 같은 모델이라도 필요한 파일을 읽고 검사를 실행하며 중단 시 상태를 남기는 환경이 갖춰졌는지에 따라 결과가 달라지므로, 모델의 능력과 그 주변 실행 구조를 함께 설계해야 한다.

[8.7 / 화면 82] 지속 실행 목표

[8.9 / 화면 84] 예약 자동화
학습 초점: 정해진 조건이나 시간에 작업을 시작하고 결과를 확인하는 방식
확정 문단: 중단된 작업을 이어가는 것과 별도로 새로운 작업을 언제 시작할지도 정할 수 있다. 예약 자동화는 정해진 시간이나 시작 조건에 맞춰 작업을 실행하고, 그 결과와 확인이 필요한 항목을 남기는 방식이다. 일정한 시각에 저장소의 검사를 수행하도록 구성할 수 있지만 작업에 필요한 접근 권한과 실행 환경이 준비되어야 하며, 실행 중 사건에 반응하는 Hooks나 목표를 유지하는 기능과 예약 시작은 역할이 다르다.
권장 자료: 예약 시각 → 실행 환경 확인 → 작업 → 결과 검토 (비교·시간선)
구성·활용: 예시: 매주 월요일 09:00 Asia/Seoul 제목 검사 실행 후 결과 기록. 같은 페이지에서 Hooks=실행 중 이벤트, Goals=완료할 결과, 예약=시작 시점을 작은 비교로 구분.
