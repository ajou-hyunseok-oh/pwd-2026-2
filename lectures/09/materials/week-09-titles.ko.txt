01. 인공지능 연구의 출발
1950~1970년대 · 기계 지능의 평가와 규칙·신경망을 이용한 초기 구현
연결: 기존 프로그래밍에서 사람이 작성하던 판단을 기계가 수행하게 하려는 연구의 출발점.
범위: 지능의 평가와 초기 구현 접근. 퍼셉트론은 입력·가중치·출력만 소개하고 학습 알고리즘은 2장에서 설명.

| 설계 번호 | 타이틀 | 서브타이틀 | 선수 개념 위치 |
| --- | --- | --- | --- |
| 1.1 | 인공지능 | 인식·언어 이해·문제 해결을 기계로 수행하는 방법의 연구 | 강의의 출발점 |
| 1.2 | 튜링 테스트 | 문자 대화에서 사람과 기계를 구별할 수 있는지 평가 | 1.1 |
| 1.3 | 다트머스 인공지능 연구 모임 | 1955년 제안과 1956년 모임에서 공유한 기계 지능 연구 의제 | 1.2, 1.1 |
| 1.4 | 기호 기반 인공지능 | 기호로 표현한 사실에 규칙을 적용해 결론 도출 | 1.3 |
| 1.5 | 퍼셉트론 | 입력의 가중합을 임곗값과 비교해 두 결과 중 하나를 선택 | 1.4 |
| 1.6 | 전문가 시스템 | 분야별 지식 기반과 추론 엔진을 이용한 판단 | 1.4, 1.5 |

  사례·범위: 조건에 따라 판단하는 프로그램과 문장을 해석해야 하는 과제의 차이
- 1.1 → 1.2: 지능적 과제의 범위에서 지능을 평가하는 기준으로 이동
  사례·범위: 상대의 정체를 모르는 평가자가 텍스트 대화를 비교하는 상황; 의식의 증명으로 확대하지 않음
- 1.2 → 1.3: 기계 지능에 관한 질문이 연구 분야로 조직되는 과정
  사례·범위: 1955년 제안과 1956년 모임을 구분한 간단한 연표
- 1.3 → 1.4: 연구 목표를 실제로 구현하는 첫 번째 접근 소개
  사례·범위: 조건에 맞는 규칙을 적용해 물체의 종류를 판별하는 흐름
- 1.4 → 1.5: 명시적인 규칙과 다른 초기 접근으로 수치 기반 판단 소개
  사례·범위: 입력 두 개와 가중치·임곗값을 표시한 판단 도식; 역전파는 사용하지 않음
- 1.5 → 1.6: 병행하던 접근 중 기호·규칙 계열의 실제 응용으로 돌아옴
  사례·범위: 장비 증상과 점검 규칙을 연결한 고장 진단; 퍼셉트론의 후속 모델로 설명하지 않음

02. 데이터 학습과 신경망
1980년대~2016년 · 모델을 학습시키는 방법과 이미지 분류·바둑 적용 사례
연결: 사람이 지식을 모두 규칙으로 작성하는 접근의 한계에서, 초기부터 병행되어 온 데이터 학습 방식의 발전과 확산으로 이동.
범위: 학습과 추론을 구분한 뒤 학습 방식·신경망 구조·대표 사례 순서로 설명. AI 겨울은 앞 시기의 배경까지 회고.

| 설계 번호 | 타이틀 | 서브타이틀 | 선수 개념 위치 |
| --- | --- | --- | --- |
| 2.1 | AI 겨울 | 기대에 못 미친 성과가 연구 지원 위축으로 이어진 시기 | 1.6, 1.5 |
| 2.2 | 머신러닝 | 데이터에서 모델의 판단 기준을 얻는 방법 | 2.1, 1.6 |
| 2.3 | 모델 학습 | 모델의 예측을 평가하고 내부 값을 반복 조정 | 2.2, 1.5 |
| 2.4 | 모델 추론 | 학습한 내부 값으로 새 입력의 결과를 계산 | 2.3 |
| 2.5 | 지도학습 | 입력과 정답을 짝지어 예측의 기준으로 사용 | 2.3, 2.4 |
| 2.6 | 비지도학습 | 정답 표시가 없는 데이터에서 유사성과 구조를 탐색 | 2.5 |
| 2.7 | 강화학습 | 행동의 결과를 바탕으로 장기 보상을 높이는 방법 학습 | 2.3, 2.5, 2.6 |
| 2.8 | 인공 신경망 | 한 층의 출력을 다음 층의 입력으로 전달하는 계산 구조 | 1.5, 2.3, 2.7 |
| 2.9 | 역전파 | 출력 쪽에서 계산을 거슬러 가중치 변화가 오차에 미치는 영향 파악 | 2.8, 2.3 |
| 2.10 | 딥러닝 | 여러 층의 신경망에서 과제에 유용한 특징을 학습 | 2.8, 2.9 |
| 2.11 | AlexNet의 이미지 분류 | 2012년 대규모 이미지 분류 대회에서 확인한 딥러닝의 성과 | 2.10, 2.5, 2.4 |
| 2.12 | AlphaGo의 바둑 수 선택 | 신경망의 수·형세 평가와 탐색을 결합한 다음 수 선택 | 2.11, 2.10, 2.7 |

인접 슬라이드 연결과 사례
- 1.6 → 2.1: 초기 구현의 성과 다음에 적용 범위와 비용의 한계 확인
  사례·범위: 규칙 유지 비용·계산 자원·과도한 기대를 함께 제시; 단일 원인이나 한 번의 사건으로 단정하지 않음
- 2.1 → 2.2: 규칙을 직접 늘리는 부담에서 데이터를 활용하는 대안으로 이동
  사례·범위: 직접 작성한 메시지 분류 규칙과 분류 사례에서 얻은 모델의 비교; 모델의 입력·내부 값·출력 소개. AI 겨울 이후에 머신러닝이 처음 발명되었다는 설명 제외
- 2.2 → 2.3: 데이터에서 판단 기준을 얻는 과정의 내부 변화 설명
  사례·범위: 예측과 학습 목표의 차이를 확인하고 가중치를 조정하는 도식; 미분 수식은 전제하지 않음
- 2.3 → 2.4: 내부 값을 바꾸는 단계와 학습된 값을 사용하는 단계 구분
  사례·범위: 이미 학습된 메시지 분류기에 처음 보는 메시지를 입력하는 상황
- 2.4 → 2.5: 학습·추론의 공통 구조를 정답이 주어지는 학습에 적용
  사례·범위: 스팸 여부가 표시된 메시지로 학습한 뒤 새 메시지를 분류
- 2.5 → 2.6: 정답이 있는 데이터와 정답 표시가 없는 데이터의 차이 확인
  사례·범위: 분류 이름 없이 비슷한 문의를 묶는 사례; 구체적인 군집 알고리즘은 정의하지 않음
- 2.6 → 2.7: 고정된 데이터의 패턴에서 행동과 결과를 통해 배우는 방식으로 확장
  사례·범위: 간단한 격자 환경에서 이동과 보상을 반복; 개발 도구를 쓰는 LLM 에이전트와 구분
- 2.7 → 2.8: 학습 방식의 구분을 마치고, 이를 구현할 수 있는 모델 구조로 관점 전환
  사례·범위: 앞서 배운 가중합 계산을 여러 층으로 연결; 각 층의 입력·출력 표시
- 2.8 → 2.9: 층이 여러 개인 구조에서 학습에 필요한 조정 방향을 구하는 문제 설명
  사례·범위: 오차의 영향이 출력층에서 앞 층으로 전달되는 그림; 역전파 계산과 가중치 갱신을 구분
- 2.9 → 2.10: 다층 구조를 학습할 방법을 바탕으로 표현 학습과 규모 확장 설명
  사례·범위: 입력에서 단순 특징과 복합 특징으로 이어지는 층별 표현 도식
- 2.10 → 2.11: 딥러닝의 구조를 이미지 분류 성과로 확인
  사례·범위: 이미지 입력과 분류 결과의 대응; CNN 세부 구조와 GPU 구현을 새 선수 개념으로 요구하지 않음
- 2.11 → 2.12: 대상의 분류에서 행동 후보를 평가하는 응용으로 확장
  사례·범위: 신경망의 평가와 후보 탐색의 역할을 도식으로 구분; 탐색 알고리즘의 상세 규칙은 다루지 않음

03. 대규모 언어 모델의 학습과 생성
2017~2020년 · 텍스트의 표현부터 Transformer의 사전 학습과 생성까지
연결: 이미지·게임에서 확인한 신경망의 활용을 언어로 확장하고, 텍스트를 표현하는 단위부터 설명.
범위: 토큰 → 수치 표현 → 관계 계산 → 모델 구조 → 학습 → 생성 → 한계와 보완. Transformer를 구성 요소보다 먼저 설명하지 않음.

| 설계 번호 | 타이틀 | 서브타이틀 | 선수 개념 위치 |
| --- | --- | --- | --- |
| 3.1 | 언어 모델 | 주어진 문맥에서 빈 곳이나 다음에 올 표현을 예측 | 2.10, 2.4, 2.12 |
| 3.2 | 토큰 | 텍스트를 처리 단위로 나누고 각 조각을 번호에 대응 | 3.1 |
| 3.3 | 토큰 임베딩 | 토큰 ID를 모델이 계산에 사용할 벡터로 변환 | 3.2, 2.8 |
| 3.4 | 어텐션 | 위치 간 관련도를 계산해 다른 토큰의 정보를 가중 반영 | 3.3, 3.1 |
| 3.5 | Transformer | 어텐션과 위치별 표현 변환을 여러 층에서 반복하는 구조 | 3.4, 3.3, 2.8 |
| 3.6 | 자기지도학습 | 가린 부분이나 뒤에 이어지는 표현을 원문에서 학습 목표로 구성 | 3.5, 2.5, 3.2, 2.3 |
| 3.7 | 사전 학습 | 폭넓은 텍스트로 여러 과제에 활용할 기반 모델을 학습 | 3.6, 3.5 |
| 3.8 | 대규모 언어 모델 | 데이터·모델·계산 규모를 늘려 여러 언어 과제에 활용 | 3.7, 3.1, 3.5 |
| 3.9 | 다음 토큰을 이용한 텍스트 생성 | 선택한 토큰을 문맥에 추가하며 출력을 순서대로 생성 | 3.8, 3.2, 2.4 |
| 3.10 | 컨텍스트 윈도 | 한 요청에서 지침·대화·자료와 출력에 사용할 수 있는 토큰 범위 | 3.9, 3.2 |
| 3.11 | 언어 모델의 환각 | 사실과 다르거나 근거가 부족한 내용을 그럴듯하게 생성 | 3.10, 3.9, 3.7 |
| 3.12 | 검색 증강 생성(RAG) | 질문과 관련된 외부 문서를 찾아 답변을 생성할 때 참조 | 3.11, 3.10, 3.9 |

- 3.5 → 3.6: 모델 구조 다음에 대량의 텍스트에서 학습 목표를 얻는 방법 설명
  사례·범위: 문장의 일부를 가리거나 앞부분으로 뒷부분을 예측; 비지도학습과 세부 분류 논쟁은 확장하지 않음
- 3.6 → 3.7: 학습 목표를 정한 뒤 그것을 대규모 데이터에 적용하는 단계 설명
  사례·범위: 대량 텍스트로 기본 모델을 만드는 과정; 지시 튜닝의 구체적 방법은 4장에서 정의
- 3.7 → 3.8: 앞서 배운 구조와 학습을 대규모 언어 모델로 연결
  사례·범위: 같은 모델을 문장 완성·요약 등 여러 과제에 적용; BERT·GPT의 사전 학습 사례를 연표에 배치하고 세부 구조 비교는 범위에서 제외
- 3.8 → 3.9: 여러 활용 중 생성형 모델이 결과를 만드는 추론 과정 구체화
  사례·범위: 다음 토큰의 여러 후보와 선택 결과; 3.5의 병렬 학습 계산과 순차 생성의 대비. 항상 최고 확률만 선택하거나 매번 재학습한다는 설명 제외
- 3.9 → 3.10: 출력 생성에 사용되는 앞선 입력의 범위와 한계 확인
  사례·범위: 지침·대화·문서가 입력 예산을 공유하는 그림; 모델별 정확한 한도는 본문 작성 시 확인
- 3.10 → 3.11: 입력 범위와 학습된 예측 방식이 사실 보장과 다름을 설명
  사례·범위: 제공하지 않은 문서의 내용을 그럴듯하게 추정하는 사례; 원인을 컨텍스트 길이 하나로 단정하지 않음
- 3.11 → 3.12: 근거가 부족한 답변을 보완하기 위해 외부 자료를 입력에 연결
  사례·범위: 질문 → 관련 안내 문서 검색 → 문서를 포함한 답변; 벡터 DB·MCP 없이 텍스트 검색으로 설명, 오류 제거 보장은 제외

  사례·범위: 일반 텍스트 사전 학습과 요청·응답 예시를 이용한 추가 학습의 구분

- 4.5 → 4.6: 대화형 요청의 내용을 재현 가능한 형태로 구체화
  사례·범위: 목표·관련 입력·제약·원하는 결과를 갖춘 요청; 역할 지정은 보조 지침이며 정확성을 보장하지 않음
- 4.6 → 4.7: 말로 전달한 조건을 구체적인 예시로 보완
  사례·범위: 일반 제목·빈 문자열·공백뿐인 제목의 처리 예시; 제로샷과 같은 과제로 비교하고 가중치 학습과 구분

  사례·범위: 공백 제거 후 빈 제목 거부·길이 제한을 가진 순수 함수; 브라우저·DB·에이전트 도구는 아직 사용하지 않음

  사례·범위: 공백뿐인 제목을 허용하는 오류의 입력·실제 결과·기대 결과 전달; 자동화 테스트 프레임워크는 도입하지 않음

05. AI 에이전트의 도구 사용
2022~2024년 · 도구를 호출하고 실행 결과를 바탕으로 다음 행동을 결정하는 구조
연결: 사람이 코드와 실행 결과를 복사하던 왕복 과정을 도구 호출로 연결하고, 결과를 관찰하며 작업을 이어가는 구조 설명.
범위: 도구 호출과 권한을 먼저 정의한 뒤 에이전트 반복과 개발 사례 제시. 멀티모달 입력 뒤 컴퓨터 사용, 개별 도구 연결 뒤 MCP.

| 설계 번호 | 타이틀 | 서브타이틀 | 선수 개념 위치 |
| --- | --- | --- | --- |
| 5.1 | 도구 호출 | 모델의 호출 요청을 받아 외부에서 실행하고 결과를 되돌려주는 방식 | 4.9, 2.4, prior-code |
| 5.2 | 도구 실행 권한 | 실행 환경이 적용하는 파일 접근·수정·외부 전송 범위 | 5.1, prior-tools |
| 5.3 | 에이전트의 실행 루프 | 도구 실행 결과를 관찰해 다음 행동이나 종료를 결정하는 반복 구조 | 5.1, 5.2, 3.10 |
| 5.4 | 에이전트의 개발 도구 | 파일 읽기·편집과 터미널 실행을 에이전트에 연결 | 5.3, 5.2, prior-tools |
| 5.5 | 에이전트의 제목 검사 함수 수정 | 에이전트가 파일을 읽고 공백 오류를 재현·수정한 뒤 다시 실행 | 5.4, 5.3, 4.8, 4.9 |

인접 슬라이드 연결과 사례
- 4.9 → 5.1: 사람이 전달하던 실행 요청과 결과를 프로그램 사이의 연결로 바꿈
  사례·범위: 모델의 도구·인자 요청 → 실행 프로그램 → 결과 반환; 모델의 텍스트 출력만으로 명령이 실행되지는 않음
- 5.1 → 5.2: 실제 기능을 실행할 수 있게 된 뒤 접근·변경 범위 설정
  사례·범위: 파일 읽기·작업 폴더 수정·외부 전송의 권한 차이; 지침 문구와 강제되는 실행 제한 구분
- 5.2 → 5.3: 한 번의 허용된 호출을 결과에 따라 이어가는 작업 구조로 확장
  사례·범위: 목표 → 행동 → 관찰 → 다음 행동 또는 종료; 반복 실행 자체를 모델 가중치 학습으로 설명하지 않음
- 5.3 → 5.4: 일반적인 행동·관찰 구조를 개발 환경의 구체적인 기능에 대응
  사례·범위: 파일 읽기·편집·터미널 실행의 입출력; Claude Code와 현재 Codex를 제품 사례로 배치
- 5.4 → 5.5: 앞서 사람이 수정하던 같은 함수를 연결된 개발 도구로 처리
  사례·범위: 함수 읽기 → 입력 실행 → 결과 확인 → 수정 → 재실행; 테스트 프레임워크·Hooks는 아직 사용하지 않음
- 5.5 → 5.6: 작업 실행 구조를 배운 뒤 여러 조건을 다루는 모델의 문제 해결 능력 설명
  사례·범위: 복합 조건의 검사 로직을 단계별로 검토; 2장의 모델 실행으로서 추론과 용어 구분, 내부 사고 공개를 정답 근거로 사용하지 않음
- 5.6 → 5.7: 문제 해결 능력에서 모델이 받아들일 수 있는 입력 형식으로 관점 전환
  사례·범위: 화면 이미지와 텍스트 설명을 함께 입력; 이미지가 자동으로 클릭 권한을 제공한다는 설명 제외
- 5.7 → 5.8: 이미지 관찰 능력과 도구 행동을 화면 조작에 결합
  사례·범위: 화면 확인 → 입력·클릭 → 변경 화면 확인; 아직 자동화 테스트 체계로 확장하지 않음
- 5.8 → 5.9: 서로 다른 개발·화면·자료 도구를 연결하는 공통 규약의 필요로 이동
  사례·범위: 도구마다 따로 연결하는 구조와 MCP 서버를 통한 연결 비교; 자체 실행 엔진·메모리·권한 보증으로 설명하지 않음

06. 에이전트의 프로젝트 맥락 관리

  사례·범위: 프로젝트 구조·관련 파일·실행 명령·현재 오류; 저장소 전체가 자동으로 입력된다고 가정하지 않음

- 6.2 → 6.3: 선별할 정보 중 반복되는 규칙을 지속적으로 제공하는 위치 정의
  사례·범위: AGENTS.md·CLAUDE.md의 역할과 적용 범위; 구체적 탐색·우선순위 규칙은 제품별 공식 문서로 확인
- 6.3 → 6.4: 프로젝트의 공통 규칙에서 특정 작업을 수행하는 재사용 절차로 확장
  사례·범위: 검사 함수 변경 시 확인할 항목과 실행 방법을 담은 스킬; MCP 연결 규약이나 별도 학습 모델과 구분
- 6.4 → 6.5: 재사용할 절차와 현재 작업에서 달라지는 진행 상태의 구분
  사례·범위: 수정 파일·직접 실행한 명령과 결과·미해결 문제를 남긴 기록
- 6.5 → 6.6: 긴 작업에서 진행 상태를 잃지 않고 입력 공간을 확보하는 방법 설명
  사례·범위: 원문 이력 → 핵심 요약과 원본 위치 → 이어서 필요한 파일 확인; 손실 없는 기억으로 설명하지 않음
- 6.6 → 6.7: 지침·절차·진행 기록을 같은 프로젝트 작업에 함께 배치
  사례·범위: 입력 화면·검사 함수·요청 처리 파일 중 관련 부분을 선택; 인증이나 미학습 프레임워크의 동작을 전제하지 않음

07. 명세에 따른 구현과 검증
2025년 후반~2026년 · 명세를 작업으로 나누고 실행 결과로 완료 여부를 판단하는 과정
연결: 프로젝트를 이해하고 작업을 이어가는 방법에서, 무엇을 완성해야 하며 결과를 어떻게 확인할지 명시하는 개발 절차로 이동.
범위: 명세·완료 기준 → 계획·작업 단위 → 검증 수단 → 구현·검증 반복 → 실행 제어 → 리뷰 → 통합 사례. 기존 소프트웨어 공학 기법을 AI 도구의 발명으로 설명하지 않음.

인접 슬라이드 연결과 사례
- 6.7 → 7.1: 현재 프로젝트의 맥락에서 앞으로 바꿀 동작을 분리해 명시
  사례·범위: 게시글 제목 조건·저장 성공 시 결과·잘못된 입력의 처리; 인증 기능은 범위에 추가하지 않음
- 7.1 → 7.2: 명세의 요구를 결과에서 확인할 수 있는 조건으로 변환
  사례·범위: 빈 제목 거부·정상 제목 저장·실패 안내 표시를 관찰 결과로 정의
- 7.2 → 7.3: 완료 상태를 정한 뒤 그 상태에 도달할 변경 순서 구성
  사례·범위: 검사 함수 → 요청 처리 → 입력 화면의 변경 순서; 확인 가능한 작업 계획을 내부 사고 기록과 구분
- 7.3 → 7.4: 전체 작업 순서를 개별적으로 완료 여부를 판단할 크기로 분할
  사례·범위: 검사 함수 변경·서버 입력 처리·화면 오류 표시로 분할; 이 단계에서는 순차 실행
- 7.4 → 7.5: 작은 작업의 결과를 사람이 매번 확인하던 과정에서 반복 가능한 검사로 확장
  사례·범위: 일반 제목·빈 제목·공백 제목·길이 경계의 입력과 기대 결과; 특정 프레임워크 문법 없이 검사 원리부터 설명
- 7.5 → 7.6: 함수의 결과 확인을 화면·요청·응답이 연결된 사용자 동작으로 확장
  사례·범위: 제목 입력 → 제출 → 오류 또는 성공 표시; Playwright는 검증 수단의 사례로 배치
- 7.6 → 7.7: 배운 검증 수단을 이미 알고 있는 에이전트 반복 구조에 연결
  사례·범위: 작업 선택 → 구현 → 검사 → 실패 관찰 → 수정 또는 완료; 처음부터 정답이라는 판단이나 무조건적인 무한 반복 제외
- 7.7 → 7.8: 반복 과정에서 빠지면 안 되는 동작을 특정 실행 시점에 연결
  사례·범위: 도구 실행 전 정책 확인·편집 후 포맷 검사; React Hooks와 구분하고 단순 알림과 실제 차단 조건을 구분
- 7.8 → 7.9: 개별 실행 장치를 작업 시작부터 종료까지 관리하는 전체 구조로 연결
  사례·범위: 실행 환경·진행 상태·검사 결과·재시도 제한을 표시한 도식; Hooks만으로 하네스 전체를 설명하지 않음
- 7.9 → 7.10: 검사가 끝난 결과를 명세·변경 범위와 대조하는 사람의 판단으로 연결
  사례·범위: 수정 전후 코드와 실제 실행 결과 대조; 검사 통과만으로 요구 충족이나 안전성을 단정하지 않음
- 7.10 → 7.11: 개별 절차를 같은 게시글 기능의 시작·종료 과정으로 통합
  사례·범위: 제목 검사 함수 → 서버 저장 처리 → 화면 피드백을 순차 완성; 다음 챕터의 병렬 실행과 비교할 기준 마련

08. 병렬 개발과 장기 작업 관리
2026년 · 분리한 변경을 통합하고 여러 실행에 걸쳐 목표와 진행 상태를 관리
연결: 검증 가능한 단일 작업 과정을 확보한 뒤, 작업을 나누어 동시에 수행하거나 여러 실행에 걸쳐 이어가는 방법 설명.
범위: 작업 독립성 → 위임·협업 → 변경 공간 분리 → 통합 → 지속 목표·재개·예약 → 개발자의 판단. Git과 장기 작업 자체가 2026년에 처음 생긴 기법이라는 설명 제외.

| 설계 번호 | 타이틀 | 서브타이틀 | 선수 개념 위치 |
| --- | --- | --- | --- |
| 8.1 | 병렬 개발을 위한 작업 분리 | 변경 범위를 나누고 화면과 서버 사이의 요청·응답을 먼저 합의 | 7.11, 7.4, 7.3 |
| 8.2 | 서브에이전트 | 목표와 자료를 전달해 하위 작업을 맡기고 별도 맥락에서 나온 결과를 회수 | 8.1, 5.3, 6.2 |
| 8.3 | 에이전트 팀 | 역할과 진행 상태를 공유해 여러 에이전트의 작업을 조정 | 8.2, 8.1, 6.5 |
| 8.4 | Git 브랜치 | 화면과 서버의 변경을 별도 커밋 이력으로 관리 | 8.3, 7.10, prior-tools |

인접 슬라이드 연결과 사례
- 7.11 → 8.1: 순차로 진행한 작업 중 의존성이 낮은 부분을 선별
  사례·범위: 입력 화면과 서버 처리의 요청·응답 형식을 먼저 합의; 단순히 작업 수를 늘리면 빨라진다는 설명 제외
- 8.1 → 8.2: 구분한 작업을 다른 실행 주체에 맡기는 기본 구조 설명
  사례·범위: 주 에이전트가 제목 검사 함수의 경계값 검토를 별도 에이전트에 위임; 항상 병렬이거나 항상 파일을 수정하는 것은 아님
- 8.2 → 8.3: 한 번의 위임에서 여러 작업 주체의 조정과 정보 교환으로 확장
  사례·범위: 화면·서버·검증 역할의 메시지와 결과 공유; 제품별 지원 범위·실험 기능 상태를 본문 작성 시 확인
- 8.3 → 8.4: 여러 작업 주체가 만드는 코드 변경을 구분할 필요에서 버전 관리 개념으로 이동
  사례·범위: 같은 기준에서 시작한 화면 변경과 서버 변경의 이력; 브랜치는 작업 폴더 자체가 아님
- 8.4 → 8.5: 이력의 분리를 실제 파일을 편집하는 작업 공간의 분리로 확장
  사례·범위: 에이전트별 디렉터리와 브랜치 연결; 별도 DB·비밀정보·네트워크 격리까지 보장하는 것으로 설명하지 않음
- 8.5 → 8.6: 분리한 코드 변경을 사용자가 이용할 하나의 기능으로 결합
  사례·범위: 게시글 입력 화면과 서버 처리 변경의 통합; 충돌 해결 후 개별 검사와 전체 등록 동작 재확인
- 8.6 → 8.7: 동시에 수행한 작업의 통합에서 여러 단계 동안 작업을 계속할 기준으로 관점 전환
  사례·범위: 기능 완성과 검증 증거·시간 또는 비용 한도·진행 불가 시 중단 조건; 영구적인 무인 실행으로 설명하지 않음
- 8.7 → 8.8: 지속할 목표가 있어도 실행이 중단되는 상황에서 안전하게 이어가는 방법 설명
  사례·범위: 완료 기록·미해결 항목을 읽고 파일 상태·이전 검사 결과의 유효성을 재확인
- 8.8 → 8.9: 진행 중인 작업의 재개와 별도로 새 작업을 언제 시작할지 정의
  사례·범위: 정해진 시각에 저장소 검사와 결과 보고; 실행 중 사건에 반응하는 Hooks와 시작 조건을 구분
- 8.9 → 8.10: 자동 실행의 범위가 넓어진 전체 흐름을 개발자의 결정과 책임으로 연결
  사례·범위: 작은 수정은 단일 에이전트, 독립 작업은 분할, 요구가 불명확하면 먼저 명세 보완; 속도와 검증 비용을 함께 판단
