[2] 45–46번 Render·Commit — 기본 설명 적합, 도식의 적용 범위 보완
UI 계산과 DOM 반영의 구분, 첫 DOM 연결, 달라진 부분만 변경하는 설명은 공식 문서와 일치.
일반적인 화면 반영 흐름을 보여주는 도식으로 적합. 다만 모든 Render가 반드시 Commit으로 이어지는 보장으로 읽으면 부정확. React는 렌더 결과를 폐기할 수 있음.
Mount → Update → Unmount의 화살표는 예시 순서임을 구분할 필요. Update는 0회 이상 가능하며 Mount 뒤 바로 Unmount도 가능.
권장: 생명주기 본문에 ‘Update는 필요할 때 0회 이상 반복’ 추가 또는 Mount→Unmount 경로 표시. Render 장에는 ‘Render 결과가 같으면 DOM 변경 없음’을 우선 보완. 렌더 폐기·중단은 심화 범위이므로 기본 슬라이드의 필수 설명으로 강제하지 않음.
출처: https://react.dev/learn/render-and-commit
      https://react.dev/reference/react/Component#render

[3] 56번 useState·58번 useRef — 적합
useState의 최초 렌더 초기 상태 준비 및 이후 현재 상태 반환은 정확.
useRef의 첫 참조 객체 생성 및 이후 같은 객체 반환, 값 변경만으로 렌더를 요청하지 않는 설명은 정확.
DOM ref의 Commit 연결 및 제거 시 null 해제는 DOM에 연결한 객체 ref에 한정한 설명으로 적합. 모든 useRef의 current가 Unmount 때 자동으로 null이 된다는 일반화는 피해야 함. 현재 본문은 ‘DOM에 연결한 ref’로 제한함.

[4] 59–61번 Effect — 실행 순서 적합, 개념적 구분 보완 필요
useEffect 호출은 Render 중, 설정 함수는 Commit 이후라는 구분은 정확. 의존성 변경 시 이전 정리→새 설정, 제거 시 정리도 정확.
공식 문서는 Effect를 컴포넌트 생명주기의 콜백으로 생각하는 방식을 피하도록 권고하며, 각 Effect의 동기화 시작→중지라는 독립적 주기를 강조.
현재 도식은 실행 시점 참고로 유효하나, 독립적 주기 설명이 없어서 Mount·Update·Unmount에 일대일 대응하는 Hook으로 오해할 여지가 있음.
권장 문구: ‘Effect는 외부 시스템과 동기화를 시작하고 정리 함수로 중지하는 작업’. ‘컴포넌트가 유지되는 동안에도 의존성이 바뀌면 중지→다시 시작’.
‘배열 생략은 매 Commit’은 ‘해당 컴포넌트의 매 Commit’으로 범위 명확화 권장. 앱의 다른 컴포넌트 Commit까지 뜻하지 않음.
빈 배열에 대한 기본 설명은 적합하며 개발 Strict Mode의 추가 설정·정리는 61번에서 이미 설명함.
‘Commit 뒤’는 브라우저가 화면을 그린 뒤와 동의어가 아님. 현재 본문은 Commit으로 표현하므로 적합. 상위 부제의 ‘화면 반영 후’는 ‘DOM 반영 후’로 바꾸면 더 명확.
출처: https://react.dev/learn/lifecycle-of-reactive-effects
