원본: [PWD Week 3] React 프레임워크를 이용한 웹 프론트엔드 개발.pdf 실제 18쪽.
범위: 2025년 슬라이드의 개념·패키지 역할·올해 표기 적합성. 검토 후 64번 부록 추가 완료 (2026-10-12). 모든 버전 조합의 설치·호환성 검증이나 최신 패치 버전 목록 작성은 이번 검토 범위가 아님.

종합 판단
생태계의 개념과 대부분의 패키지 역할은 2026년에도 유효. 원문 그대로 재사용하면 Vite 번들러와 React Router 패키지 설명은 오래된 정보를 전달. 나머지는 선택 가능한 도구의 예로 소개하고, 필수 설치 목록이나 공식 표준으로 설명하지 않는 것이 적절.

수정 필요
1. Vite: ‘빌드 시 Rollup’은 Vite 7까지의 설명. 2026-03-12 공식 Vite 8 출시에서 Rolldown을 통합 번들러로 채택. ‘개발 서버·프로덕션 빌드 도구 (Vite 8부터 Rolldown 기반)’으로 변경.
2. React Router: URL과 UI 연결·중첩/동적 경로 역할은 유효. 현재 공식 설치 문서는 npm i react-router 및 react-router import 사용. v7의 react-router-dom은 호환을 위한 재내보내기, v8에서는 해당 패키지 제거를 공식 업그레이드 문서가 명시. 올해 자료는 ‘React Router (react-router)’ 중심으로 표시.

유효하지만 표현 보완
3. 생태계 정의: ‘React 코어만으로는 부족한 작업’ 대신 ‘React와 함께 UI 개발에 필요한 기능을 확장하는 라이브러리·도구·프레임워크와 커뮤니티’가 중립적.
4. 작은 코어+조립: 선택·조합 방식은 유효. 공식 React 문서는 새 앱에 프레임워크로 시작하는 방식을 권장하면서 기본 학습·제약이 있는 경우 Vite 등으로 직접 구성하는 경로도 안내. 직접 조립만이 유일한 방식처럼 표현하지 않을 것. 부록에서 Next.js·React Router 등의 프레임워크를 한 범주로 추가 가능하되 심화 사용법은 불필요.
5. 다양한 런타임: 브라우저·서버·모바일·데스크톱 활용 개요는 유지 가능. react-dom 하나가 모든 플랫폼을 렌더하는 것처럼 설명하지 말고 플랫폼별 렌더러·프레임워크와 결합한다는 의미로 표현.
6. NPM 네트워크·커뮤니티 규모: 패키지·플러그인·사례가 풍부하다는 취지는 유효. ‘빠르게 축적’, ‘폭발적으로 늘어남’은 올해 증가율을 따로 검증하지 않았으므로 ‘다양한 도구와 사례를 선택·활용’ 정도로 간결화.
7. react-hook-form: 폼 상태·검증 관리 역할은 유효. 비제어 입력을 활용하지만 Controller로 제어 컴포넌트도 지원. ‘비제어 입력만 지원’으로 이해하지 않도록 ‘폼 입력·검증 관리’ 중심으로 소개.
8. @tanstack/react-query: 서버 데이터 조회·캐시·동기화·무효화·재시도 역할은 유효. ‘관리 표준’은 공식 필수 표준처럼 읽히므로 ‘서버 상태 관리 라이브러리’로 변경.
9. axios: Promise HTTP 요청·인터셉터 역할은 유효. React 전용 또는 필수 도구가 아니라 브라우저·Node.js 공용 라이브러리로 표시. TanStack Query와는 HTTP 요청 자체 vs 서버 데이터 캐시·수명 관리라는 역할 차이.

유지 가능
10. react: 컴포넌트와 Hooks를 사용하는 UI 핵심 라이브러리.
11. react-dom: 웹 DOM 렌더링 및 서버 HTML 생성 관련 API. 현재 브라우저 DOM 설명은 맞지만 패키지의 모든 기능을 포괄하는 정의는 아님.
12. @emotion/react, @emotion/styled: CSS-in-JS, css prop·테마, styled 컴포넌트 지원. 선택 가능한 스타일링 도구의 예로 유지.
13. @testing-library/react/dom/jest-dom/user-event: React·DOM 테스트와 사용자 상호작용 검증 도구로 유효. 테스트 실행기(Vitest/Jest 등) 자체와 구별. 설치 예제를 만들 경우 테스트 도구는 devDependencies로 구분하고 DOM 패키지의 중복 설치를 피하도록 공식 설치 안내 확인.
14. react-icons: 아이콘 컴포넌트 묶음. react-spinners: 로딩 표시 컴포넌트. react-toastify: 알림 메시지 UI. 모두 특정 UI 기능을 위한 선택 도구 예로 유지 가능.
15. web-vitals: 실제 웹 성능 지표 측정 라이브러리. React 전용이 아닌 공용 웹 도구로 별도 분류.

package.json 판단
오른쪽 목록은 2025년 프로젝트에서 선택한 패키지 예시이며 보편적인 React 기본 설치 목록이 아니다. 모든 항목을 함께 설치해야 한다는 의미로 사용하면 부정확하다.
^19.1.1 같은 표기는 정확한 설치 버전 고정이 아니라 허용 범위이므로 번호가 작년 것이라는 이유만으로 코드 오류라고 판정할 수 없다. 실제 설치 버전은 해석 가능한 범위와 lockfile 등에 따라 달라진다.
올해 부록은 긴 버전 목록보다 ‘분야 / 도구 / 역할’ 표로 구성하는 편이 학습 목적에 적합. package.json을 유지한다면 올해 검증한 별도 실행 프로젝트의 파일로 갱신하고, Vite·테스트 실행기 등 개발 의존성과 scripts까지 완전한 예인지 구분해야 한다.
