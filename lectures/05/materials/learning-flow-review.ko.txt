2026-10-12 · 1~63번 학습 흐름 검토
대상: 현재 slide-map.json의 63장, 실제 본문·예제·결과·생명주기 SVG, 프로젝트 생성 기록.
범위: 학습 순서, 필요한 선행 설명, 중복, 예제 독립성과 개념 대응. 이번 검토에서 슬라이드 본문은 변경하지 않음.

전체 판단
React의 필요성과 설계 철학 → 개발 환경 → 컴포넌트·JSX·Props → 상태와 화면 갱신 → Hooks의 큰 순서는 적절하다. 대규모 재배치보다 초반 생명주기의 정보량, 환경 일관성, 핵심 비교 설명과 종합 연결을 우선 보완하는 편이 좋다.

구간별 판단
1~9: 배경·역할·역사·활용 사례. 6번의 Relay·GraphQL·코드 로딩 계층은 React 입문 목표보다 깊으므로 산업 사례로 짧게 다루는 것이 적절. 3번은 구간 표지이므로 4번과 제목이 유사해도 본문 중복이 아님.
10~21: 컴포넌트·재사용·선언형 UI·Virtual DOM의 개요. 15번과 19번은 책임 분리라는 같은 메시지를 카운터와 상품 목록으로 반복. 15번은 작성 방식, 19번은 변경 결정의 책임으로 역할을 구분해 강의 시간을 배분할 것. 20번은 개요, 45~46번은 구체적인 상태 예제에 따른 심화로 유지 가능.
22~25: 도구 확인 → 실제 Vite 메뉴 → Hello World 순서가 명확. 이후 예제의 언어와 이 환경이 일치하지 않는 문제는 우선 수정 필요.
26~41: 함수 컴포넌트 → JSX → Props → 조합·조건·목록·정적 화면 순서가 적절. 28번에서 후속 개념을 너무 많이 앞당기고, 34번은 개념보다 예제 식별자에 기대며, 38번은 실행을 위해 별도 Props와 table 문맥이 필요.
42~54: 이벤트 → 상태 → Render·Commit → 상태 업데이트·공유·보존 순서가 좋다. 44번의 State 정의, 43번의 함수 전달 규칙, 48번의 함수형 갱신 필요성 대비가 보완 대상. 41번의 상품 검색 화면을 완성해 전체 연결을 확인하는 부분이 없음.
55~63: Hook 소개 → 호출 규칙 → Ref → Effect → 의존성 → 정리 → 커스텀 Hook → 추가 학습 목록의 순서가 적절. 60번 의존성 배열 비교와 57~62번 호출 규칙 연결 필요. 63번은 개요로 충분하며 상세 구현을 늘리지 않는 편이 적절.

우선 보완 사항
1. 24~25번과 43~62번의 실행 환경 불일치 [높음]
24번은 TypeScript 템플릿, 앞 예제는 .tsx, 43번 이후 다수는 .jsx이다. JSX 예제로 읽으면 타당하지만 학생이 기존 App.tsx에 그대로 옮기는 흐름에서는 오류가 생긴다.
실제 생성 프로젝트의 tsconfig.app.json과 의존 패키지로 58·61·62번 예제를 .tsx로 검사했다. 58번 ref.current의 null 가능성, 61번 pName 타입 누락·문자열 상태에 null 대입, 62번 Props 타입 누락·반환 배열의 숫자/함수 혼합 타입 오류 확인.
권고: 생성 환경에 맞춰 후반 예제를 TypeScript로 통일하거나, JavaScript 예제 실행 환경을 명확히 제시. .jsx 라벨만 .tsx로 바꾸는 것으로 해결되지 않음.

2. 28번 생명주기의 선수 개념과 정보량 [높음]
Props·State의 사용법 이전에 Effect·의존성·정리 및 useMemo/useCallback/useLayoutEffect의 위치까지 소개. 도식의 기술적 보정과 별개로 초심자가 전체를 이해하기에는 이르다.
권고: 위치는 유지하되 본문·기본 도식은 Mount/Update/Unmount와 Render/Commit 중심으로 이해. Hook 이름과 상세 시점은 56~61번에서 다시 연결. 상세 도식을 강의용 참고로 활용할 경우 28번에서 외울 내용으로 취급하지 않을 것.

3. 44번 State 자체의 정의와 Props 대비 [높음]
현재 정의가 useState의 구조 중심이다. State가 무엇인지, 일반 변수·Props와 어떻게 다른지는 11번의 짧은 개요에 많이 의존한다. useState 사용 구조는 이미 충실하므로 유지.
권고: ‘컴포넌트가 다음 렌더에서도 기억하는 값’이라는 State 정의와 ‘Props는 전달받고, State는 해당 컴포넌트에서 관리’라는 짧은 대비 추가. useState가 Hook이라는 연결만 여기서 소개하고 56번의 도입 배경 설명은 유지.

4. 59~60번 의존성 배열 형태의 비교 누락 [높음]
59번은 배열 생략, 60번은 [pName]인데 생략과 []의 차이는 설명하지 않는다.
권고: 생략 = 이 컴포넌트가 Commit될 때마다 실행, [] = 의존성 변경으로 재실행하지 않음, [pName] = 최초 및 pName 변경 후 실행을 비교. []를 영구적으로 정확히 한 번이라고 설명하지 말 것. 제거 후 다시 생성되는 경우 및 개발 확인 동작과 구분.
추가로 함수·객체 등 Effect 안에서 사용하는 컴포넌트 내부 값도 의존성 검토 대상이라는 점은 강사 메모에서 보완 가능.

5. 41~52번 개별 개념에서 실제 상품 검색으로의 연결 부족 [중간]
정적 상품 UI, 파생값, 제어 입력, 상태 끌어올리기는 각각 설명되지만 검색어와 재고 조건이 실제 목록에 연결되는 완성 예제가 없다.
권고: 기존 독립 예제는 유지하고 52번 이후 짧은 종합 시연 또는 보조 자료에서 입력 → 상태 → 필터 계산 → 목록의 흐름 확인. 긴 통합 코드를 한 장에 몰아넣지 않아도 된다.

6. 43번 이벤트 핸들러의 전달과 호출 구분 [중간]
onClick={handleClick}은 있지만 onClick={handleClick()}과의 차이는 없다. 51번의 e.target.value/checked를 이해하는 이벤트 객체 연결도 짧다.
권고: ‘실행 결과가 아니라 함수를 전달’ 한 줄과 필요한 인자를 전달할 때 화살표 함수로 감싼다는 짧은 비교. 51번에서는 e.target이 변경된 입력 요소라는 설명 보완.

7. 48번 함수형 업데이트를 쓰는 이유의 대비 [중간]
함수 두 번으로 +2는 잘 보이지만 setCount(count + 1)을 두 번 호출하면 같은 스냅샷에서 같은 다음 값을 요청한다는 대조가 없다.
권고: 같은 값으로 두 번 요청하면 +1, 계산 함수 두 번이면 +2라는 짧은 비교를 47번 스냅샷과 연결. 별도의 배칭 심화 강의를 추가할 필요는 없음.

8. 57번과 62번의 호출 규칙 연결 [중간]
57번은 컴포넌트 함수 최상위만 명시하고 62번은 커스텀 Hook 내부에서 useState를 호출한다. 허용 범위가 확장되어 보일 수 있다.
권고: 62번에서 커스텀 Hook 내부 최상위에서도 호출 가능하고 같은 순서 규칙을 따른다는 한 줄 보완. 57번에서 아직 배우지 않은 상세 커스텀 Hook 설명을 앞당길 필요 없음.

9. 실제 개발 화면과 콘솔 결과의 조건 [중간]
실제 Vite 생성 프로젝트 main.tsx는 루트 StrictMode를 사용한다. 반면 45·60·61번의 로그 결과는 추가 개발 확인 실행을 제외한 기본 흐름이다. React 공식 문서는 개발 StrictMode에서 Effect의 추가 설정·정리 주기를 명시한다.
권고: 이전 사용자 요청대로 경고 문구를 본문에 반복하지 말고, 강사 시연 환경을 검증 환경과 맞추거나 실행 결과가 기본 동작을 보여주는 것임을 강사 메모에 기록. 기본 개발 서버에서 로그 개수가 항상 동일하다고 안내하지 않을 것.

10. 34·36·38번의 설명 일관성 [중간~낮음]
34번 본문이 App/ProductName/pName 사례 해설에 치우쳐 있다. Props를 속성 형태로 전달하고 매개변수로 받는다는 일반 구조가 더 필요. pName은 직접 정한 이름임을 짧게 명시 가능.
36번은 export type과 export default를 모두 사용하지만 기본 내보내기와 이름 있는 내보내기의 차이를 보여주지 않음. 현재 핵심이 단순 파일 연결이면 불필요한 export type을 줄이거나 최소한의 차이를 보완.
38번 라벨에 ‘부모가 전달’이라는 기존 표현이 남아 있고, product Props와 table/tbody 문맥을 요구하는 예제다. 사용자 선호에 맞춰 ‘전달받는 입력’으로 수정하고 내부 데이터·일반 요소를 사용하는 독립 사례로 간결화 가능.

중복 검토
- 12~13번 ↔ 35번: 구성·재사용을 다시 다루지만 앞은 개요 사례, 뒤는 분리 기준. 유지 가능.
- 15번 ↔ 19번: 같은 명령형/선언형 메시지의 반복 강도가 높음. 작성 방식과 변경 책임으로 설명 범위를 구분하거나 한쪽을 빠르게 진행.
- 20번 ↔ 28번 ↔ 45~46번: 화면 갱신 흐름이 반복. 개요/전체 생명주기/단계별 구체 예제로 역할을 구분하고 28번을 가볍게 할 것.
- 33번 내부: ‘형제 관계 유지’, ‘div 없이’, ‘불필요한 묶음 없이 배치’는 내용이 겹침. DOM 차이와 배치 효과로 두 항목 정도로 축약 가능.
- 44번 ↔ 56번: useState의 초기/현재 상태 반환 설명 반복. 44번은 사용 구조, 56번은 Hook의 도입·공통 규칙으로 중심을 구분.
- 51번 내부: 입력값과 상태 일치를 설명하는 3번째·5번째 항목의 중복. 일치 관계와 검사·초기화·공유 효과로 정리 가능.
- 40번 ↔ 54번: 불필요한 중복 아님. 안정적인 key로 목록 항목 유지 vs key 변경으로 의도적 초기화라는 상반된 활용.
- 52번 ↔ 62번: 불필요한 중복 아님. 같은 상태 공유 vs 로직만 재사용하고 상태는 독립이라는 핵심 대비. 이 차이를 구두로 연결하면 학습 효과가 큼.
- 2·3·10·17·22·26·42·55번 등의 표지와 후속 본문의 유사 제목은 내용 중복으로 계산하지 않음.
