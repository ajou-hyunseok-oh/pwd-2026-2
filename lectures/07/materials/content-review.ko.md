## 이전 구성 — 2026-11-02 PostgreSQL 소개 챕터 재작성

제공된 [PostgreSQL 조사 문서](postgresql-research.ko.txt)에 따라 36~49쪽을 표지 1장·본문 13장의 PostgreSQL 소개로 교체했다. DB 설계와 겹치던 자료형·테이블 생성·관계 구현·CRUD·JOIN의 상세 설명은 이 구간에서 제거했다. 50~52쪽 Supabase 소개와 53쪽 실습 안내는 유지하며 전체 53장이다. 기존 49쪽 Supabase 구분 표지는 새 PostgreSQL 내용으로 대체하고 50쪽부터 관리형 플랫폼의 구체 사례로 연결한다.

### 내용과 시각 자료

- 37~40: 객체 관계형 DBMS 개요·활용 분야, POSTGRES/Postgres95/PostgreSQL 연혁, 2025 개발자 설문과 확산 설명 모형, 라이선스와 운영 비용의 구분
- 41~43: 재고 변경·주문 기록의 함께 확정/취소, READ COMMITTED 두 세션의 읽기 시점, 고정 열과 JSONB 부가 정보의 결합
- 44~45: 5개 확장의 기능 표, 반경 500m 공간 SVG, 질문→임베딩→검색→별도 생성 모델의 RAG 흐름
- 46~49: 관리형 PostgreSQL과 호환 엔진·서비스, 언어별 개발 도구, PostgreSQL/MySQL 비교, 실제 도입·운영 판단 표

공식 보도자료의 Slonik PNG 원본을 37쪽에 배치했다. 다른 표·도식은 공식 자료와 제공 문서를 바탕으로 한·영 HTML/SVG로 자체 구성했다. [챕터 자료 안내](postgresql/README.md)와 [이미지·도식 출처](postgresql/source-manifest.json)에 원본 URL·이미지 해시·기술 근거를 기록한다. 코드 예제는 JSON 값 하나이며 실제 DB 조회 결과로 표시하지 않는다.

### 기술적 검토

설문은 2025년 자료임을 표시하고 시장점유율이나 미확인 비율로 해석하지 않았다. 확산 선순환은 설명 모형으로 구별한다. MVCC는 일반 조회와 READ COMMITTED의 문장 시작 시점을 전제로 하고 잠금·쓰기 충돌의 관리를 별도로 남긴다. JSON/JSONB의 원문 보존과 인덱싱 차이를 구별한다. 클라우드 제품은 PostgreSQL 관리형과 PostgreSQL 호환 서비스로 나눴으며 MySQL 8.4의 JSON·윈도 함수·CTE도 공통 지원 기능으로 표시한다. pgvector는 검색 확장이며 임베딩 생성·답변 생성 모델과 분리한다.

- 공용 JSON 포매터와 구문 검사 통과. 기존 설계 사례의 FD·키·정규형·분해 검산도 통과
- 공용 `npm test`: 13개 덱 구조·138개 코드 블록/274개 언어 변형·작성 하네스 통과

## 학습 순서와 예제

DB/DBMS와 관계형 테이블 → 엔티티·관계 → 스키마·키·제약 → 정규화 → PostgreSQL과 SQL → Supabase 순서로 배치한다. 후보 키·슈퍼키·주요 속성과 부분·이행 종속을 정규형보다 먼저 설명한다. 함수 종속은 식당 ID가 이름을 결정하는 사례로 연결하고, 2NF·3NF는 분리된 테이블을 표로 제시한다. 관계 구현 SQL은 빈 식당 테이블에 외래 키·UNIQUE를 추가한 뒤 제보 INSERT RETURNING → 식당 INSERT → SELECT → JOIN → UPDATE → DELETE 순서다. 반환된 제보 id와 식당 id가 1이라는 예제 조건을 라벨로 명시한다. RLS가 켜진 공개 API는 해당 역할의 권한과 정책을 함께 확인하며, SQL Editor 관리자 조회 결과를 API 접근 검증으로 간주하지 않는다.

## DBMS 전체 구조도 변경

사용자의 요청에 따라 MVC 그림 대신 클라이언트 ↔ 웹 서버 ↔ DBMS와 관리 대상 데이터베이스를 보여주는 자체 도식으로 변경했다. 05·06 강의에서 네 요소를 명확히 구분하는 그림은 찾지 못했다. 04의 React 도식은 서버·데이터베이스를 함께 표시하며 06의 클라이언트–서버 그림은 DB가 없다. 웹 서버가 PostgreSQL의 클라이언트가 되고 DBMS가 데이터를 관리하는 관계는 PostgreSQL 공식 아키텍처 문서를 기준으로 했다: https://www.postgresql.org/docs/current/tutorial-arch.html. Supabase Data API처럼 자체 웹 서버 없이 이용하는 구성도 존재하며, 이 그림은 웹 서버를 경유하는 예시다. https://supabase.com/docs/guides/api

DBMS 슬라이드의 본문을 한 열로 정리하고, 도식은 배경 패널 없이 큰 브라우저·웹 서버·데이터베이스 아이콘과 요청·응답·질의·결과 흐름으로 변경했다. DBMS는 색상으로 강조한다. KO/EN 발표·인쇄·모바일 검사 및 대표 발표 화면을 확인했다.
