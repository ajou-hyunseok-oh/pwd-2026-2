# 챕터 평가와 반복 수정 절차

8주차 챕터 1의 03~09번을 평가하고 수정한 과정을 다음 챕터에서 재사용하는 작업 기준. 각 장의 존재 목적을 정한 뒤 본문과 사례를 함께 고치고, 간결성과 화면을 확인한 다음 챕터 전체를 다시 평가한다. 보강에는 설명 추가뿐 아니라 중복 제거와 유용한 시각 자료의 복원도 포함한다.

## 적용 범위

- 기존 본문이 있고 사용자가 평가·수정을 요청한 챕터에 적용한다. 평가만 요청한 경우에는 평가 결과만 제시한다.
- 반복 개선을 요청받으면 해당 범위의 평가, 수정, 재생성, 검증, 재평가를 장마다 재승인받지 않고 수행한다. 여러 챕터가 범위이면 챕터 순서대로 완료하고 다음 챕터로 진행한다.
- 확정된 제목·순서·학습 범위·핵심 사례·공용 스타일을 유지한다. 새 장이나 새 주제를 추가하는 것은 기본 수정 범위에 포함하지 않는다. 본문 없는 골격에는 내용을 채우지 않는다.
- 명시적으로 요청한 범위 변경은 수행한다. 범위가 불분명하고 기존 구조 안에서 해결할 수 없는 경우에만 문제와 구체적인 대안을 제시한다. 나머지 수정은 계속 진행한다.
- 사용자 교정이 일반 작성 규칙보다 우선한다. 제거 요청한 문구나 후속 개념을 자동으로 복원하지 않는다.
- 이 문서는 요청받은 작업 안에서 반복하는 절차다. 예약 실행이나 주기적인 자동화는 설정하지 않는다.

## 반복 작업 순서

### 1 챕터 전체의 맥락과 장별 역할 설정

챕터의 제목, 모든 본문·사례, 이전 챕터의 결론과 다음 챕터의 도입을 먼저 읽는다. 학습자가 챕터를 마친 뒤 설명할 수 있어야 하는 내용을 정하고, 각 슬라이드의 역할을 아래 항목으로 기록한다.

| 항목 | 확인할 내용 |
| --- | --- |
| 존재 목적 | 학생이 이 장에서 새로 이해할 내용 한 문장 |
| 이전 내용과 연결 | 어떤 개념이나 문제를 이어받는가 |
| 설명 범위 | 이 장에서 설명할 내용과 후속 장에 남길 내용 |
| 사례의 역할 | 어떤 입력·관계·처리·결과로 본문을 확인하는가 |
| 인접 장과 차이 | 앞 장의 반복인지, 필요한 적용·통합인지 |

이 표는 검토 기록으로 사용한다. 슬라이드마다 목적·예고·요약 상자를 추가하는 서식이 아니다.

### 2 실제 구현과 기술적 근거 확인

실습 구현을 언급하면 관련 코드와 데이터 경로를 확인한다. UI 동작에 대한 주장은 필요한 화면을 실행해 확인한다. API 처리 주장은 라우트·컨트롤러·서비스 등 관련 경로와 대조하고, 단순 문구 수정마다 전체 앱을 다시 실행하지는 않는다.

실제 구현, 가정한 설계, 개념 사례를 구분한다. 확인하지 않은 구현을 사실로 쓰거나, 사례의 성공·실패 결과를 실행한 결과처럼 설명하지 않는다. 기술적 사실이 불확실하거나 변경 가능한 API·정책을 다루면 공식 문서로 확인하고 근거를 자료 기록에 남긴다.

### 3 슬라이드별 평가와 수정

슬라이드 순서대로 다음 관점에서 평가한다. 각 문제는 해당 문장·표의 셀·도식 요소를 지정하고, 문제의 이유와 수정 방향을 함께 기록한다. 적절한 부분은 유지한다.

| 관점 | 통과 기준 | 문제가 있을 때의 수정 |
| --- | --- | --- |
| 목적과 범위 | 한 장에서 새로 가르칠 내용이 명확함 | 서브타이틀·본문의 초점을 맞추고 후속 개념을 덜어냄 |
| 논리 전개 | 필요성·정의·요소의 역할·관계가 자연스럽게 이어짐 | 빠진 인과 관계를 보완하고 무관한 나열을 정리 |
| 본문과 사례 | 본문만으로 원리를 이해하고 사례가 그 원리를 보여줌 | 일반 설명과 특정 식별자 해설을 분리하고 사례의 대응을 수정 |
| 정확성 | 입력·주체·저장 정보·결과와 보호 범위가 맞음 | 과장된 효과나 잘못된 결과를 바로잡음 |
| 선수 개념 | 사례 이해에 필요한 개념을 이미 배웠음 | 이미 배운 요소로 사례를 단순화 |
| 시각 자료 | 표·흐름·화면이 서로 다른 설명 역할을 함 | 유용한 원본 자료를 유지하고 역할이 겹치는 부분만 정리 |
| 정보량 | 핵심을 읽기 쉽고 불필요한 반복이 없음 | 부가 설명·중복 흐름·반복 하단 안내를 먼저 제거 |

본문은 일반적인 개념·역할·관계를 설명하고 사례는 이를 구체화한다. 앞 장에서 사용한 서비스, 계정, 요청, 식별자를 가능한 한 이어받되, 새 개념을 설명하는 데 필요한 요소만 더한다. 식별자 통일을 이유로 서로 다른 실제 대상을 합치지 않는다.

비교는 표, 순서는 흐름, 실제 입력·결과는 화면을 우선 검토한다. 원본 이미지가 무엇을 설명하는지 확인한 뒤 편집한다. 새 도식을 넣었다는 이유만으로 유용한 기존 이미지를 삭제하지 않는다. 모든 슬라이드에 같은 블록 수·같은 레이아웃·같은 하단 요약을 강제하지 않는다.

과밀하면 중복 제거, 문장 정리, 자료 배치 조정 순으로 해결한다. 핵심 조건과 인과 관계를 생략하거나 글자를 줄여 억지로 맞추지 않는다. 강의 중 예제를 짚는 해설은 검토 문서에 둘 수 있지만, 핵심 원리를 구두 설명에만 맡기지 않는다.

### 4 원본 반영과 검증

작성 원본을 수정하고 생성기를 통해 HTML·번역·관련 자료를 갱신한다. KO/EN을 함께 수정하며, 생성된 HTML만 직접 고치지 않는다.

8주차의 작성 경로:

- 제목·서브타이틀: `lectures/08/scripts/title_outline.py`
- 설명의 내용 계약: `lectures/08/scripts/paragraph_outline.py`
- 본문·구성: `lectures/08/scripts/slide_body.py`
- 사례·시각 자료: `new_resources.py`, `reused_resources.py`, 필요할 때만 `resource_blocks.py`
- 생성: `build-slides.py`; 변경에 해당하는 개요·본문·자료 배치·출처 생성기와 `--check`
- 스타일: 공용 작성 스타일을 우선 사용하고 필요한 차이만 `lectures/08/body.css`에 반영

저장소의 공용 검사와 변경에 맞는 검증을 수행한다. 문구·사례 수정은 해당 슬라이드의 KO/EN 발표·1280×720 인쇄·390px 모바일을 확인한다. 챕터 전체를 고치면 해당 챕터 전체를 확인하고, 공용 스타일을 바꾸면 영향을 받는 슬라이드까지 범위를 넓힌다. 수치적인 경계 검사와 함께 실제 화면을 육안으로 확인한다.

검사 통과, 실패, 환경 때문에 미실행한 항목을 구분한다. 일부 검사 통과를 전체 검사 통과로 보고하지 않는다. 생성 결과의 동기화와 재생성 후 변경 보존도 확인한다. 직접 시작한 로컬 서버가 있으면 종료하고 프로세스와 포트 해제를 확인한다. 사용자 서버는 종료하지 않는다.

### 5 챕터 재평가와 재수정

수정한 챕터를 처음부터 읽고 장별 역할, 사례의 연속성, 필요한 개념의 누락, 중복, 후속 개념의 선행 설명을 다시 평가한다. 첫 장에서 제기한 문제 중 이 챕터가 해결하는 범위와 후속 챕터에 남기는 범위가 분명한지도 확인한다.

남은 문제가 있으면 해당 장과 영향을 받는 인접 장만 다시 수정·검증한다. 같은 문제가 반복되면 표현만 바꾸지 말고 역할 설정이나 사례 선택으로 돌아간다. 올바른 문장을 취향에 따라 계속 바꾸지 않는다.

## 완료 기준과 기록

다음 조건을 충족하면 해당 챕터의 반복을 끝낸다.

1. 각 장의 목적과 인접 장과의 차이가 명확하고, 불필요한 중복·선수 개념 역전이 없다.
2. 본문만으로 핵심 원리를 이해하고 사례의 요소·처리·결과가 설명에 부합한다.
3. 구현 주장에 근거가 있으며, 가정과 실제 동작을 구분하고 효과를 과장하지 않는다.
4. 유용한 시각 자료를 유지하며, 과밀·잘림·겹침을 해결했다.
5. KO/EN과 생성 결과를 동기화하고 필요한 검사를 통과했다.
6. 챕터 재평가에서 구체적인 내용·화면 문제가 남지 않았다.

검사를 실행할 수 없으면 완료 조건을 충족했다고 쓰지 않는다. 내용 수정은 마칠 수 있지만 검증 제한과 남은 작업을 별도로 기록한다. 반복 횟수나 점수 상승 자체를 완료 기준으로 삼지 않는다.

기존 회차의 기록 형식을 우선 사용하고, 각 수정에 다음 정보를 남긴다: 화면 번호와 ID, 존재 목적, 구체적인 문제, 수정 근거, 실제 변경, 구현·출처 근거, 검증 결과, 남은 문제. 챕터 기록에는 장별 역할과 마지막 재평가 결과를 남긴다. 이미 있는 검토 파일을 갱신할 수 있으면 같은 내용을 새 파일에 중복 기록하지 않는다.
