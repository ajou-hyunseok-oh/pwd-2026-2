# 1개념 1슬라이드

사용자의 2026-10-10 지시에 따라 05의 새 본문과 이후 회차의 본문 작성에 적용한다. 05의 적용 구간은 현재 화면 26 이후이며, 표지와 챕터 표지는 본문 개념 수에 포함하지 않는다. 그대로 옮기도록 지정한 04 React 원본 24장은 재분할하지 않는다.

이 문서는 한 장의 개념 범위를 정한다. 실제 본문은 [개념 설명 작성 기준](body-explanation.md)에 따라 정의·구성 요소의 역할·관계와 구조를 일반화해 설명한다. 한 장에 개념 하나만 두거나 예제의 설명을 자연스럽게 연결하는 것만으로 본문 작성이 완료되지는 않는다.

## 한 장의 범위

- 본문 한 장은 독립적으로 설명하고 확인할 수 있는 학습 개념 하나를 다룬다. 제목에서 그 개념을 특정할 수 있어야 한다.
- 서로 다른 정의와 사용 목적을 각각 배워야 하는 개념은 장을 나눈다. 한 예제에 함께 등장하거나 같은 API 계열에 속한다는 이유로 묶지 않는다.
- 이미 배운 개념은 새 개념을 설명하는 전제나 짧은 대조로 사용할 수 있다. 새 개념 두 개를 각각 정의하는 비교 본문은 만들지 않는다.
- 정의에 속하는 사용 조건·구문·사례·예외·실패 처리는 같은 장의 하위 설명이다. 이 항목들을 자동으로 별도 개념으로 세지 않는다.
- 설명량이나 코드 길이 때문에 같은 개념의 사례를 여러 장으로 이어갈 수 있다. 이때도 각 장의 제목과 서브타이틀에서 해당 사례의 범위를 구분한다.

## 제목과 서브타이틀

제목은 개념의 이름을 직접 쓴다. 서브타이틀은 해당 장에서 설명할 역할·동작·적용 범위를 짧게 쓴다. 서브타이틀에 다른 독립 개념을 추가하거나 본문 항목을 나열하지 않는다. 제목만 나누고 기존 복합 본문을 그대로 붙이지 않는다.

예를 들어 `조건부 렌더링과 목록`은 `조건부 렌더링`, `목록 렌더링`, `목록 항목의 key`로 나눈다. `Render`와 `Commit`, `Effect 의존성`과 `Effect 정리 함수`도 각각의 장으로 작성한다. 반면 Hydration의 초기 화면 일치 조건, 커스텀 Hook의 호출별 상태 독립성, 낙관적 UI의 실패 시 복원은 해당 개념의 하위 설명으로 둔다.

## 학습 순서와 선수 개념

사용자의 2026-10-10 후속 교정에 따라 한 장의 개념 수와 별도로 학습 순서를 검토한다. 한 장의 제목이 하나여도 본문·표·예제가 뒤에서 배울 개념을 먼저 설명하거나 전제로 삼으면 재작성 대상이다.

- 각 장의 정의·표·예제에 필요한 선수 개념을 적고, 이전 회차 또는 앞 장에서 어디까지 배웠는지 확인한다. 개요에서 이름만 본 개념을 사용법까지 배운 것으로 취급하지 않는다.
- 아직 배우지 않은 독립 개념의 정의·사용 규칙·호출 위치별 동작을 앞 장에서 설명하지 않는다. 구성 요소를 일반화한다는 이유로 뒤 장의 개념까지 끌어오지 않는다.
- 이미 본 기본 표기를 다시 사용할 수는 있다. 예를 들어 원본 Hello World에서 본 태그를 함수 컴포넌트 예제에 쓰되 JSX 자체의 정의는 JSX 장에서 설명한다. 이름이나 표기를 보았다는 이유만으로 상세 동작을 알고 있다고 가정하지 않는다.
- 아직 배우지 않은 개념을 알아야 예제의 핵심 흐름을 이해할 수 있으면 이미 배운 개념으로 단순화하거나 표·도식으로 바꾼다. 필요한 문법을 지워 잘못된 실행 코드를 만들거나, 구현을 숨긴 함수로 옮겨 놓고 의존성이 해결되었다고 판단하지 않는다.
- 확정된 제목·순서는 우선 유지한다. 순서를 유지한 채 설명할 수 없는 경우에는 구체적인 선수 관계와 순서 변경의 근거를 먼저 검토한다.

05의 적용 사례: 함수 컴포넌트 장에서 Props·JSX의 정의 제거, 파생값 예제의 제어 입력을 버튼 이벤트로 교체, 목록 변환은 표로 설명한 뒤 key 장에서 완전한 목록 코드 제시, 데이터 재검증은 폼·Server Function 없이 원본과 캐시의 관계로 설명.

검토 기록에는 현재 장, 먼저 등장한 후속 개념, 해당 개념의 학습 장, 앞 장에서 필요했던 이유, 수정 방법을 남긴다. 단어 검색은 조사 보조 수단이며 자동 검사의 통과나 이름의 등장 횟수로 학습 순서가 적절하다고 판정하지 않는다.

## 작성 순서와 확인

1. 원본의 제목·정의·코드 안에 등장하는 학습 개념을 조사한다. 제목에 드러나지 않은 개념도 확인한다.
2. 개념별 제목과 서브타이틀을 먼저 작성하고 기존 화면과의 대응을 기록한다. 이전 한 장을 항상 두 장으로 나누는 규칙은 두지 않는다.
3. 이 목록을 기준으로 개념·구성 요소·관계와 구조의 일반 설명을 작성하고, 이를 보여주는 사례를 선택한다. 한 장에 새 독립 개념이 추가되면 목록부터 수정한다. 코드 없이 본문을 읽어도 개념을 이해할 수 있는지, 코드가 그 장의 개념을 실제로 보여주는지 함께 확인한다.
4. 개념 설명 개수·코드 개수·열 개수는 고정하지 않는다. 개념의 정의와 필요한 설명량에 맞춰 레이아웃을 선택한다.

자동 검사는 제목의 존재·번역·누락·원본 대응·화면 잘림을 확인하는 보조 수단이다. 제목의 접속사를 금지하거나 정의 개수만 세어 의미상 한 개념이라고 판정하지 않는다.

05의 제목 작성 원본은 `lectures/05/scripts/title_outline.py`, 본문 작성 원본은 `slide_body.py`다. `lesson.py`가 둘을 조합해 61개 본문을 구성한다. `index.html`은 실제 본문 덱이고 `--titles-only`로 생성하는 `titles.html`은 같은 순서의 제목 검토용이다. 분할 전 번호는 `materials/pre-concept-slide-map.json`에 보존하며 현재 번호와 혼동하지 않는다.

각 본문에는 `data-wd-concept`로 중심 개념 ID를 기록한다. 공용 검사에서 동등한 최상위 정의 두 개를 다시 추가하지 못하도록 확인한다. 이 구조 검사와 별개로 제목·설명·예제의 의미 일치를 검토한다.
