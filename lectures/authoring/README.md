## 작성 계약

새 본문에는 [1개념 1슬라이드 원칙](one-concept.md)을 우선 적용한다. 제목·서브타이틀 단계에서 개념을 분리하고 기존 화면과 대응시킨 뒤 본문을 작성한다. 사용 조건과 사례는 해당 개념의 하위 설명으로 둔다. 이 규칙은 01~04에서 추출한 기준에 더해 사용자가 명시적으로 정한 작성 원칙이다.

본문의 내용은 [개념 설명 작성 기준](body-explanation.md)을 함께 적용한다. 본문에는 정의·구성 요소의 역할·관계와 구조를 일반화해 설명하고, 코드는 이를 확인할 구체적인 사례로 선택한다. 강사가 예제의 이름과 문장을 짚으며 말할 코드 해설을 본문으로 옮기지 않는다. 코드 없이 본문을 읽어도 핵심 개념과 구조가 이해되어야 한다.

본문·표·코드의 선수 개념은 [학습 순서 기준](one-concept.md#학습-순서와-선수-개념)으로 별도 검토한다. 아직 배우지 않은 개념의 정의나 사용 규칙을 앞 장에 넣지 않는다. 해당 개념이 필요한 예제는 앞서 배운 내용으로 단순화하거나 관계를 보여주는 표·흐름으로 바꾼다.

강의 첫 장에는 [강의 표지 공통 형식](cover.md)을 적용한다. 01~03의 주차형과 04의 주제형을 구분하며, 단일 회차 덱의 기본은 주차형이다. 학기·공식 과목명·주차·주제·회차 표기의 역할과 표지 전용 스타일을 이 문서에서 확인한다.

1. 현재 HTML에서 표지·챕터를 포함한 화면 번호와 안정적인 ID를 확인한다. 작성 원본, 생성기, 번역, 코드 포매터, 검증 경로를 찾는다. 05는 `scripts/lesson.py` → `scripts/build-slides.py` → `index.html`·`lecture-content.js`·`materials/slide-map.json`이다.
2. 제목과 리드는 구체적인 대상·개념·동작을 표현한다. 본문 설명은 짧은 명사형 구문으로 작성한다. 경어·질문형 제목·제작 방법·다음 장 예고·반복 요약을 넣지 않는다. 실행 조건은 해당 코드의 라벨이나 개념 설명에 둔다.
3. 개념 묶음은 **개념 - 짧은 정의**를 첫 줄에 두고 구성 요소의 역할·관계·구조를 설명한 뒤 필요한 조건·예외를 배치한다. 앞 문장에서 소개한 대상을 다음 문장이 구체화하도록 연결하며, 짧은 명사형으로 줄이더라도 주체·대상·관계를 보존한다. ` - `는 정의, ` · `는 나열, ` → `는 처리 순서에 사용한다. 코드·URL·식별자는 일괄 치환하지 않는다.
4. 설명+코드, 비교 표, 순서·흐름, 실행 화면 중 학습 목적에 맞는 구성을 선택한다. 모든 장에 코드 1개나 설명 3개를 강제하지 않는다. 표지·챕터에는 본문 코드를 넣지 않는다. 결과는 정의와 구분해 표시하며 코드의 실제 동작과 일치시킨다.
5. 코드는 역할·파일명을 표시하고 완전한 예제와 발췌의 실행 조건을 구분한다. 공용 `pre.wd-code[data-wd-code]`와 포매터를 사용한다. 글자를 줄이거나 CSS 자동 줄바꿈으로 긴 코드를 억지로 맞추지 않는다. 먼저 코드를 간결화하고 폭·배치를 조정한다. 새 API의 동작을 변경할 때는 공식 문서로 확인한다.
6. 출처와 제작 메모는 숨김 `aside`와 자료 기록에 남긴다. 모든 장에 챕터 이름·출처·수동 페이지 번호·하단 안내를 반복하지 않는다. 학습에 필요한 실제 링크·실습 절차는 해당 내용 안에서 유지한다.

## 재사용할 구현

`packages/web-deck/authoring.css`를 공용 CSS 다음에 불러온다. 본문 섹션은 `.wd-lesson-slide.wd-slide--content`, 본문은 `.wd-lesson-body`, 정의 묶음은 `.wd-lesson-concepts`를 사용한다. 개념의 `dt > strong`과 `dd`를 분리한다. 제목에 `nowrap`을 강제하지 않는다. 좁은 화면은 한 열이며 코드의 가로 스크롤을 허용한다.

05의 생성기에서 클래스·블록 렌더링과 검증 경로를 재사용한다. `05/scripts/title_outline.py`는 확정된 개념별 제목, `slide_body.py`는 해당 개념의 본문 블록을 정의하고, `lesson.py`에서 둘을 조합한다. 설명 개수나 코드를 자동으로 채우는 고정 패턴은 두지 않는다. 내용에 특화된 레이아웃은 회차별 CSS에 추가한다. `data-wd-authoring="v1"`을 덱 루트에 표시하면 공용 하네스 검사 대상이 된다. 05 이후에 본문이 있는 덱에는 이 표시와 공용 스타일이 필수다.

사용자가 원본을 그대로 옮기도록 지정한 구간은 원본의 내용·순서·형식·번역·실행 예제를 유지한다. 05 첫 번째 챕터의 `data-wd-import="04/react"` 구간은 04 React 덱 24장 전체이며 공용 `.wd-lesson-*` 형식으로 다시 쓰지 않는다. `scripts/react_import.py`가 원본 HTML과 번역을 가져오고 원본 CSS·데모를 재사용한다. `tests/authoring-imports.cjs`가 전체 구간의 원본 일치를 확인하고, `lectures/05/scripts/check-react-import.cjs`가 KO/EN 발표·인쇄·모바일 화면과 데모를 대조한다.

## 완료 기준

```sh
python3 lectures/05/scripts/build-slides.py
node packages/web-deck/scripts/code-examples.cjs --write --lecture 05
npm test --prefix packages/web-deck
# 저장소 루트의 HTTP 서버와 Playwright 경로가 필요
PLAYWRIGHT_PATH=/path/to/playwright node lectures/05/scripts/check-slides.cjs
```

코드 포매터의 `--lecture`에는 수정한 회차를 지정한다. `check-slides.cjs`는 `LECTURE=06`처럼 회차를 선택할 수 있다. 공용 진입점은 `packages/web-deck/tests/authoring-layout.cjs`다. `DECK_URL`은 저장소 루트 서버, `REVIEW_OUTPUT`은 검토 산출물 경로다. 새 회차도 같은 검사를 사용한다.

- 정적 검사: 번역·HTML 기본값·코드 서식과 구문, 개념 위계·문체·불필요한 반복 영역 확인
- 실제 렌더: KO/EN 전체 장의 발표·1280×720 인쇄·390px 모바일에서 잘림·겹침·코드 가로 초과 확인
- 육안 검토: 표지·챕터·대표 개념·긴 코드·표 또는 흐름 등 서로 다른 레이아웃의 캡처 확인
- 내용 검토: 코드 없이 본문의 개념·구성 요소·관계와 구조를 이해할 수 있는지 확인한 뒤 예제와 대응. 본문·표·코드에 필요한 선수 개념의 학습 위치 확인. 예제 입력·행동·결과 및 실행 환경 대조. 상태·cleanup 같은 동작은 해당 예제 검사 실행. 판단 근거를 자료의 검토 기록에 보관
- 재생성: 생성기와 포매터를 다시 실행해 결과가 유지되는지 확인

현재 자동 검사는 모든 문장의 기술적 정확성·학습 순서·개념 설명의 적합성·적절한 레이아웃 선택을 판정하지 않는다. [본문 검토 기준](body-explanation.md#본문-검토의-통과-기준)은 별도로 내용 검토하고, 자동 검사 통과만으로 완료를 판단하지 않는다. 실행하지 않은 검사를 완료 기록에 적지 않는다.
