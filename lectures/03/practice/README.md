# 3주차 실습: 상품 주문 코드 읽고 완성하기

HTML·CSS와 화면 이벤트·요청 코드를 제공한다. TypeScript로 수량 검증, 주문 계산, 할인 정책을 완성하며 **실행 예측 → 코드 읽기 → 작은 수정 → 반례 검증 → 설명**을 연습한다. 프레임워크, 디자인, 결제 서비스 구현은 요구하지 않는다.

## 실행

Node.js 22 이상과 npm을 준비하고 이 폴더에서 실행한다. 최초 설치에는 인터넷이 필요하다.

```sh
npm ci
npm start
```

`http://127.0.0.1:4303`을 연다. 파일을 더블클릭해 열지 않는다. 시작 상태에서도 상품 목록은 보이지만 주문은 TODO 안내로 실패한다. 두 번째 터미널에서 `npm run watch`를 실행하면 저장할 때 JavaScript가 다시 만들어진다. **빌드 성공 후 브라우저를 새로고침**한다. 또는 서버를 종료하고 `npm start`를 다시 실행한다.

```sh
npm run check
npm run bugs
npm test
```

`check`는 타입 검사, `bugs`는 읽기용 JavaScript 오류 재현, `test`는 필수 기능 검증이다. **초기 `check`는 통과하고 `test`는 실패하는 것이 정상**이다. 컴파일 성공이 요구사항 충족을 뜻하지 않음을 확인한다. 브라우저는 `dist`의 JavaScript를 실행하므로 `dist` 대신 `src`를 수정한다.

## 파일과 수정 범위

| 파일 | 역할 | 학생 작업 |
|---|---|---|
| `index.html`, `styles.css` | 화면과 스타일 | 제공, 읽기 |
| `src/types.ts` | 상품·결과·정책·상태 타입 | 읽기, 타입 오류 실험 |
| `src/order.ts` | 수량 검증과 주문 계산 | TODO 1–3 필수 |
| `src/policies.ts` | 일반·회원 가격 정책 | TODO 4 필수 |
| `src/main.ts` | 이벤트 → 주문 계산 → 요청 → 화면 | 제공, 흐름 추적 |
| `src/ui.ts` | DOM 확인, `filter`·`map`, 화면 갱신 | 제공, 읽기 |
| `src/api.ts`, `fixtures/` | 요청, `unknown` 검증, 실패 사례 | 제공, 읽기 |
| `src/adapters.ts` | 외부 형식 → 내부 상품 | TODO 5 선택 |
| `reading/` | 오류 재현과 타입 실험 | 예측 후 실행 |
| `review.md` | 예측·검증·설명 기록지 | 작성 후 제출 |
| `solution/`, `instructor.md` | 완성 예제와 해설 | 실습 이후 비교용 |

## 진행 순서: 권장 90분

슬라이드 41–52의 실습 소개 30분 이후 별도로 진행하는 시간 예시다. 단계별 상세 질문과 제출 기준은 [실습 안내](../materials/practice-guide.ko.md)를 따른다.

1. 10분: `reading/bugs.js`를 읽고 A–D 결과를 예측한 후 실행한다.
2. 15분: `types.ts`와 `main.ts`에서 이벤트·입력·함수·반환·화면의 연결을 찾는다.
3. 25분: `order.ts` TODO 1–3을 구현하고 빈 입력과 재고 경계를 확인한다.
4. 15분: `policies.ts` TODO 4를 완성하고 타입 오류 실험을 수행한다.
5. 15분: 자동 검증과 요청 실패·재시도 확인을 진행한다.
6. 10분: 동료에게 코드 흐름을 설명하고 `review.md`를 정리한다.

선택 Adapter 과제는 별도 15–20분이다. `http://127.0.0.1:4303/?fixture=valid`는 학생 Adapter를 사용한다. `?fixture=missing`, `?fixture=wrong`은 검증 단계에서 실패해야 한다. 기본 URL은 제공 변환을 사용하므로 선택 과제를 구현하지 않아도 필수 과제를 끝낼 수 있다.

## 주문 규칙

- 상품은 노트 3,000원/재고 5개, 펜 1,500원/재고 10개, 필통 8,000원/재고 0개다.
- 수량은 빈 값·공백을 먼저 거부하고 `Number()`로 변환한다. 유한한 양의 정수이며 재고 이하여야 한다. `2abc`, `Infinity`도 거부한다. 이 실습은 `Number()`가 변환하는 `2.0`, `2e0`을 2로 허용한다.
- 상품이 없으면 실패 결과를 반환한다. 조회 배열과 상품을 수정하지 않는다.
- 일반 정책은 상품 금액 그대로, 회원 정책은 10% 할인한 **결제 금액**을 반환한다. 원 미만은 버린다. 예: 3,001원 → 2,700원.
- 순수 계산 함수는 검증된 상품 가격과 수량을 받는다. 외부 데이터의 구조 검증은 제공된 API 경계의 책임이다.
- 실제 결제·서버 저장·재고 차감은 없다. 요청 대기 중 중복 제출을 막고 실패 이후 다시 주문할 수 있어야 한다.

## 제출

소스, 잠금 파일, 실행 안내와 작성한 `review.md`를 제출한다. `node_modules`, `dist`, 강사용 `solution`·`instructor.md`는 제출하지 않는다. 제출 장소와 기한은 수업 공지를 따른다. AI를 사용했다면 질문, 적용한 변경, 직접 확인한 반례를 기록한다.
