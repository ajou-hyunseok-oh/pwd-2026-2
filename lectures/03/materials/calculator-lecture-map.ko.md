# 3주차 강의 구성안 · TypeScript 계산기 중심

## 구성 원칙

완성 계산기의 동작을 먼저 확인하고, 입력에서 결과까지 코드를 읽은 뒤, 해당 코드에 나타난 패러다임과 디자인 패턴을 설명합니다. 실습 구현과 개념 설명에 동일한 함수·타입·입력 사례를 사용합니다.

기준 프로젝트는 [`lectures/03/calculator`](../calculator/README.md)입니다. 이 문서는 실행 예제를 바탕으로 한 강의 연결안입니다. 현재 61장 슬라이드에는 기존 상품 주문 예제가 남아 있으며, 기존 확정 제목·서브타이틀과 본문을 이 문서에서 자동 변경하지 않습니다.

웹 프로그래밍 언어의 역사와 JavaScript·TypeScript의 역할은 기존 도입부로 유지할 수 있습니다. 이후 문법·패러다임·패턴에서 계산기 코드를 공통 사례로 사용합니다. 개념을 처음 읽을 때는 필요한 코드 조각만, 구조를 설명할 때는 앞서 읽은 함수들의 호출 관계를 보여 줍니다.

## 기준 실행 흐름

```text
계산 버튼 / Enter
  → submit 이벤트
  → 문자열 입력 수집
  → 연산·각도 단위 확인
  → x 검증, 이항 연산이면 y 검증
  → 연산 함수 선택·호출
  → 오류 또는 유한한 결과 반환
  → 성공 시 이력 추가
  → 화면 상태와 DOM 갱신
```

오류는 발생 지점에서 결과 값으로 반환하고 성공 이력에 넣지 않습니다. 함수 안의 순서와 함수 사이의 역할을 구분해 읽습니다.

## 개념 설명에 사용할 코드

### 타입과 검증

`src/types.ts`의 판별 유니온을 먼저 읽습니다.

```ts
export type Result<T> =
  | { ok: true; data: T }
  | { ok: false; code: ErrorCode; message: string };
```

`ErrorCode`는 같은 파일에 정의된 오류 코드 유니온입니다. `src/calculator.ts`의 실제 분기를 이어 읽습니다.

```ts
const x = parseNumber(input.x);
if (!x.ok) return x;
```

이후 `x.data`는 숫자입니다. 타입 좁히기가 접근할 수 있는 속성을 결정하고, `parseNumber`의 실행 시 검증이 입력 내용의 유효성을 결정합니다.

### 명령형 처리와 순수 함수

`src/calculator.ts`는 검증, 단항·이항 분기, 함수 호출, 결과 확인을 순서대로 수행합니다. `solution/operations.ts`의 계산 함수는 인수를 받아 결과를 반환합니다. 두 역할을 나란히 읽고, 계산 함수가 DOM과 이력을 변경할 필요가 없는 이유를 설명합니다.

학생은 `12 / 3`과 `12 / 0`을 추적하면서 어느 분기에서 실행이 끝나는지 표시합니다. 순수 함수라는 특성과 명령형 구문 사용 여부는 서로 배타적인 분류가 아닙니다.

### 클로저와 Strategy

`src/main.ts`의 조립 지점입니다.

```ts
mountCalculator(createCalculator(parseNumber, operations));
```

`createCalculator`가 반환한 함수는 전달된 검증 함수와 연산 목록에 접근합니다. 실제 선택·실행 구문은 다음과 같습니다.

```ts
result = strategies.binary[operation.id](x.data, y.data);
```

호출부는 공통 함수 계약을 사용하고 실제 계산은 선택된 함수가 수행합니다. `tests/calculator.test.mjs`의 `Strategy 교체` 검사는 호출부를 유지한 채 주입한 함수가 실행되는지 확인합니다. 클래스 계층을 추가하지 않아도 함수 값으로 이러한 구조를 만들 수 있습니다.

단항·이항 함수의 계약을 구분한 이유도 검토합니다. 모든 연산을 한 함수 타입에 억지로 맞추는 대신 필요한 인수의 차이를 명시합니다.

### 상태와 캡슐화

`src/history.ts`의 `#entries`, `add`, `list`, `clear`를 읽습니다. 상태를 보관하는 객체가 이력을 최대 5개로 제한하고 복사본을 반환하는 방식입니다. `app.ts`의 이벤트 함수는 계산 결과에 따라 이 객체와 화면 상태를 변경합니다.

이력 클래스는 객체지향 캡슐화의 작은 예제입니다. 별도의 Singleton이나 Observer 클래스를 도입할 이유는 없습니다.

## 기존 주제와의 대응

번호는 기존 구성안의 **원안 번호**입니다. 현재 슬라이드의 실제 페이지 번호와 다릅니다.

| 원안 주제 | 계산기에서의 연결 |
| --- | --- |
| 04~06 값·타입·변환·조건 | 문자열 입력, `Number`, 빈 값과 유한성 검사 |
| 07~12 배열·함수·객체·참조 | 연산 목록 검색, 콜백·클로저, 이력의 `map`과 복사 |
| 13 DOM 이벤트 | `submit`에서 계산 호출, `input`에서 이전 결과 초기화 |
| 15~17 유연성과 오류·검증 | 함수 전달, 잘못된 값·공유 참조, 타입 검사와 실행 시 검증 |
| 20~25 타입 계약·유니온·좁히기 | 함수 타입, `Result`, 연산 ID, `find`의 `undefined`, 판별 분기 |
| 28~29 제네릭·모듈·구조적 타입 | `Result<T>`, 함수 계약과 모듈별 역할 |
| 30 명령형·절차적 처리 | 검증 → 연산 선택 → 실행 → 결과 반환 |
| 31 순수 함수·불변성 | 계산 함수, 입력 보존, 이력 복사본 |
| 32 캡슐화 | 계산 이력 클래스 |
| 33 이벤트·비동기 | 이벤트는 계산기, 비동기 요청은 별도 짧은 예제 |
| 34 선언형 UI·반응형 계산 | 같은 결과 표시를 별도 프레임워크 예제로 비교 |
| 35 패러다임 조합 | 계산·절차·이벤트·상태·DOM의 역할 구분 |
| 36~37 Strategy | 연산별 함수 목록, 함수 타입, 주입·선택·교체 |
| 38~40 Adapter·패턴 적용 기준 | 외부 형식 연동이 필요한 별도 사례와 비교 |
| 41~52 실습·검증·리뷰 | 계산기 요구사항, TODO, 경계값, 코드 설명 중심으로 교체 |

원안 14의 Promise·async/await, 26~27의 `any`·`unknown`·외부 데이터 검증은 짧은 독립 예제로 설명합니다. 계산기에는 이를 위한 가짜 서버 요청을 추가하지 않습니다. `toRadians`의 단위 변환만으로 Adapter 적용 사례를 구성하지 않습니다.

## 선택 확장: 절댓값

기본 실습을 마친 경우 단항 연산 `abs`를 추가하며 변경 범위를 확인할 수 있습니다.

1. 강사가 제공 HTML에 `data-operation="abs"`인 절댓값 버튼 추가.
2. 학생이 `UnaryOperation`에 `'abs'` 추가.
3. `operationCatalog`에 단항 연산 항목 추가.
4. `operations.unary`에 절댓값 함수 등록, 정상·음수·0 테스트 추가.

공통 실행 함수와 이벤트 연결은 유지됩니다. 연산을 새로 추가하면 타입·목록·화면 등록은 필요하며, Strategy가 모든 파일 변경을 없애는 것은 아닙니다. 이 확장은 필수 TODO에 포함하지 않습니다.

## 슬라이드 작성 기준

- 실제 프로젝트에서 발췌한 코드, 해당 입력, 실행 결과를 한 주제에 배치.
- 관련 개념과 핵심 코드만 표시하고 강사용 운영 설명은 별도 문서에 보관.
- 필요한 코드 예제에 검은 배경·녹색 Consolas 형식 적용.
- 역사·전체 구성·실습 요구사항 등은 표나 흐름을 사용.
- 계산기로 직접 다루지 않는 개념은 독립 예제로 구분.

코드의 공식 문서 근거와 자체 설계 범위는 [강사용 안내](../calculator/instructor.md#공식-자료와-재구성-범위)에 기록합니다.
