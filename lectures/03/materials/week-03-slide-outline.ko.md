# 3주차 강의 슬라이드 구성안

작성일: 2026-09-16  
대상: 웹서비스 개발 입문자  
구성: 1·2교시 통합 강의 100분 + 실습 소개 30분, 휴식 별도  
분량: 통합 강의 40장 + 실습 소개 12장 = 총 52장

## 1. 작성 및 구성 규칙

1. 제목은 해당 페이지의 핵심 주제를 직접 지칭하는 구체적인 명사형 문구로 작성한다.
2. 서브타이틀은 제목의 주제를 소개하는 완결된 한 문장으로 작성한다.
3. 질문형·비유형·추상적인 제목과 내용 없는 전환용 제목을 사용하지 않는다.
4. 5분에 2장 내외는 분량의 가이드이며, 한 주제를 두 장으로 나누는 고정 형식을 적용하지 않는다.
5. 각 장에는 하나의 중심 개념을 두고, 이를 설명하는 짧은 코드 또는 코드 비교를 배치한다.
6. 앞에서 배운 데이터·함수·문법을 다음 장에서 재사용하고, 새로운 학습 관점으로 전환하는 지점에는 챕터 경계를 둔다.
7. 챕터명은 슬라이드 상단의 구분 표식으로 사용하며, 별도의 내용 없는 챕터 표지 슬라이드는 추가하지 않는다.
8. 역사적 사실과 교육용 재구성 코드를 구분하고, 프레임워크 문법은 JavaScript·TypeScript 자체 문법과 구분한다.
9. 패러다임은 코드 구성의 관점, 디자인 패턴은 반복되는 설계 문제의 해결 방식으로 구분한다.
10. 표의 ‘핵심 내용·코드 예제’와 ‘학습 연결’은 제작자·강사용 메모이며, 슬라이드에 전부 표시하지 않는다.

## 3. 공통 예제와 난도 기준

- 서비스 예제: 상품 목록에서 상품을 선택하고 수량·할인을 적용해 주문하는 화면.
- 공통 데이터: 상품 `id`, `name`, `price`, `stock`과 주문 수량 `quantity`.
- JavaScript 단계: 값과 연산 → 주문 계산 함수 → 상품 객체와 배열 → 사용자 이벤트 → 비동기 상품 조회.
- TypeScript 단계: 동일한 코드에 타입 추가 → 가능한 상태 표현 → 외부 데이터 확인 → 함수 사이의 계약 표현.
- 설계 단계: 계산·상태·실행 흐름 분리 → 할인 정책 교체 → 외부 상품 형식 변환.
- 구현 필수: 값·변수·조건·반복·함수·객체·배열, 기본 타입, 유니온과 narrowing.
- 읽기·개념 이해 중심: 클로저, 프로토타입, 제네릭, 객체지향, 선언형·반응형 UI, 디자인 패턴.
- 제외 또는 후속 학습: 프로토타입 체인 상세 알고리즘, 복잡한 `this` 바인딩, 고급 타입 연산, 모나드, 복잡한 상속 구조, 프레임워크 설치와 전체 API.
- 슬라이드 예제는 한 장당 대체로 5~10줄로 유지하고, UI 골격·에러 표시·외부 요청 코드는 제공한다.

### 코드 및 설명의 정확성 기준

- JavaScript는 타입이 없는 언어가 아니라 값에 타입이 있는 동적 타입 언어로 설명한다.
- `const`는 재할당을 제한하며 객체의 깊은 불변성을 보장하지 않는다.
- 함수형 코드를 `map`·`reduce` 사용 여부만으로 판정하지 않는다.
- TypeScript 타입 표기와 타입 단언은 실행 시 입력을 검증하거나 변환하지 않는다.
- 타입 검사, JavaScript 출력, 실제 실행은 구분해 설명한다.
- 외부 응답의 `response.ok` 확인과 JSON 데이터 검증은 별도의 단계다.
- `async`는 무거운 계산을 자동으로 별도 스레드에 보내지 않는다.
- 구조적 타입 설명에서는 객체 리터럴의 추가 속성 검사와 충돌하는 단순화를 피하고 기존 상품 변수를 전달하는 예제를 사용한다.
- 제네릭 첫 원소 예제는 빈 배열을 고려해 `T | undefined`를 반환한다.
- Strategy는 함수로도 구현할 수 있으며, Adapter라는 이름을 붙였다고 외부 검증이 자동으로 수행되지는 않는다.
- 디자인 패턴 예제는 본 강의용 설계안이며 언어 표준의 의무 규칙으로 제시하지 않는다.

### 실습 범위와 준비물

- 필수: 44–48장의 오류 재현, 입력 검증, TypeScript 전환, 타입 오류 수정, 할인 정책 분리.
- 확장: 49장의 제공 코드 일부를 완성하는 Adapter 과제.
- 공통 검증: 필수 구현은 필수 시나리오로 평가하고, 외부 데이터 형식 검증은 확장 과제를 수행한 경우 평가한다.
- 제공할 자료: 화면·이벤트 골격, 실패를 재현할 요청 모의 코드, 상품 fixture, 시작 코드, 단계별 해설, README, 타입 검사 설정.
- 프레임워크 설치와 UI 스타일 작성은 실습 목표에 포함하지 않는다.
- 이 문서는 슬라이드 구성안이며 실제 슬라이드 파일과 실습 프로젝트는 별도 제작 대상이다.
