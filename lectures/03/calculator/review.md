## 2. 타입 오류 읽기

`reading/type-errors.ts.txt`를 `src/type-experiment.ts`로 복사하고 `npm run check`를 실행합니다. 각 오류를 값의 타입과 함수 계약으로 설명한 뒤 수정합니다.

| 코드 | 오류 이유 | 수정 |
| --- | --- | --- |
| `const operation: OperationId = 'plus'` | | |
| `add('2', 3)` | | |
| `result.data.toFixed(2)` | | |

수정 후 타입 검사를 통과시킵니다. `any`, 타입 단언(`as`), non-null 단언(`!`)으로 검사를 우회하지 않습니다.

## 3. 계산 흐름 추적

`createCalculator`가 반환한 함수에 다음 입력을 전달한다고 가정합니다.

```ts
{ operation: 'divide', x: '12', y: '3', unit: 'deg' }
```

호출 순서대로 함수 이름, 인수, 반환값을 기록합니다. `y`를 `'0'`으로 바꿨을 때 어느 함수에서 실패가 만들어지고 어느 분기에서 반환되는지 표시합니다.

```text
함수 / 인수 / 반환값


```

`operation`을 `'sqrt'`로, `x`를 `'9'`, `y`를 `'잘못된 입력'`으로 바꾼 경우도 추적합니다. `y`를 검사하지 않는 이유를 연산 타입과 연결해 설명합니다.

## 5. 구조 설명

각 답변에 근거가 되는 파일과 코드 구문을 적습니다.

1. `Result<number>`는 어떤 두 형태로 구성되는가? `if (!result.ok)` 이후에 접근할 수 있는 속성은 무엇인가?
2. `createCalculator`가 반환한 함수는 어떤 값을 기억하는가?
3. `divide`와 화면을 바꾸는 함수는 외부 상태에 미치는 영향이 어떻게 다른가?
4. `strategies.binary[operation.id]`는 실행할 함수를 어떻게 선택하는가?
5. `CalculationHistory.list()`가 배열과 항목을 복사하는 이유는 무엇인가?
6. `formatNumber`에서 표시 자릿수를 제한해도 계산의 부동소수점 오차가 사라지지 않는 이유는 무엇인가?
