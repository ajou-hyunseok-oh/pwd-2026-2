CSS 규칙의 구조

CSS는 규칙(Selector + Declaration)의 집합

Selector

스타일을 적용할 대상을 가리키는 부분

  • 태그 · 클래스 · ID — h1, .btn, #app
  • 결합자: 자식, 자손, 형제 — >, (공백), +, ~
  • 상태 · 의사클래스 — :hover, :focus-visible, :disabled
  • 의사요소 — ::before, ::after

Declaration

중괄호 안에 작성하는 속성과 값의 한 쌍

  • color: #111; · margin-top: 8px;
  • 여러 선언이 모여 declaration block을 구성

style.css

* {

JavaScript와 화면 동작

사용자 행동과 데이터에 반응해 문서를 바꾸는 재료 · 바뀐 문서는 브라우저가 다시 그림

JS가 화면을 바꾸는 흐름

  1. 이벤트 발생 (클릭 · 입력 · 페이지 로드)
  2. JS가 문서에서 요소를 찾아 내용 · 속성 · 스타일을 읽고 수정
  3. 브라우저가 변경된 부분을 다시 렌더링
  4. JS가 다룰 수 있는 것
    • 문서: 요소 찾기 · 텍스트와 속성 변경 · 요소 생성과 삭제 → DOM
    • 스타일: 클래스 토글 · 인라인 스타일 변경
    • 데이터: 서버 요청 · 저장 · 계산

script.js

function changeText() {
  const intro = document.getElementById('intro');
  const messages = [
    '웹 개발은 정말 재미있어요!',
    'JavaScript로 상호작용을 만들 수 있습니다.',
    'GitHub Pages로 무료 호스팅이 가능해요!',
    '계속 공부하면 더 멋진 것을 만들 수 있어요!'
  ];

  const randomMessage =
    messages[Math.floor(Math.random() * messages.length)];

  intro.textContent = randomMessage;
}

SEO (Search Engine Optimization)

웹페이지의 태그와 링크 구조를 개선하여 검색엔진의 검색 결과 페이지에 잘 노출되도록 최적화하는 과정

HTML 생성 방식과 라우팅

CSR · SSR · SSG · URL과 라우터

웹 브라우저 렌더링 방식

HTML을 누가, 언제 생성하는가에 따라 세 가지 방식으로 구분

CSRClient-Side Rendering

빈 HTML → JS 다운로드 → 화면 생성

장점페이지 로드 후 사용자 인터랙션에 빠르게 반응 · 자주 업데이트되는 페이지에 유리 단점초기 로딩이 느리고, 크롤러가 자바스크립트를 실행해야 내용을 인식하므로 SEO에 불리
사례 소셜 미디어 플랫폼(Facebook, Instagram), 대시보드, 웹 기반 게임

SSRServer-Side Rendering

서버에서 완성된 HTML → 즉시 표시

장점빠른 초기 로딩 · 검색엔진이 쉽게 크롤링하므로 SEO에 유리 단점서버 부하로 인한 서버 비용 증가
사례 뉴스 사이트와 블로그, SEO가 중요한 전자 상거래 사이트

SSGStatic Site Generation

빌드 시 HTML 생성 → CDN 제공

장점빠른 로딩 · SEO에 유리 · 서버 부하가 적고 전 세계에 빠르게 콘텐츠 제공 단점동적인 콘텐츠가 많으면 빌드와 배포 과정이 반복적으로 필요
사례 개인 블로그 또는 포트폴리오 사이트, 마케팅 랜딩 페이지

웹서비스를 더 빠르고 안전하게 만들 수 있게 미리 준비된 설계도와 도구 묶음 · 개발과 관련된 반복 작업을 표준 방식으로 제공해 개발자의 시행착오를 줄이는 것이 목적

구성요소

  • 구조 — 폴더 · 파일 규칙, 레이어드 아키텍처(컨트롤러 · 서비스 · 모델 등)
  • 러닝키트 — 라우터, 미들웨어, ORM · 쿼리 도구, 폼 · 검증, 인증, 국제화, 테스트
  • 빌드 · 런타임 — 번들링, 트랜스파일(예: TypeScript), 코드 스플리팅, SSR · SSG 지원
  • 생태계 — 플러그인, CLI, 베스트 프랙티스 문서

종류

  • 프론트엔드(UI) — React, Vue, Angular, Svelte
  • 백엔드(API) — Express / NestJS(Node), Django / FastAPI(Python), Spring Boot(Java), Laravel(PHP), Rails(Ruby)
  • 풀스택(프론트 + 백엔드) — Next.js, Nuxt, SvelteKit, Remix

선택 기준

  • 팀 역량 · 언어 — JS / TS는 Next.js · NestJS, Python은 Django / FastAPI
  • 렌더링 방식 — CSR / SSR / SSG / ISR 필요 여부 (SEO, 초기 로드 속도 요구)
  • 호스팅 · 배포 — Vercel · Netlify(서버리스)와 컨테이너 · 쿠버네티스 중 선택
  • 생태계 — 문서 · 커뮤니티 · 플러그인의 풍부함

이 강의의 선택 프론트엔드 React + Vite(4주차) · 백엔드 Node.js + Express(6주차) · 데이터베이스 PostgreSQL + Supabase(7주차) · 배포 Vercel(9주차)

Node.js

Chrome V8 JavaScript 엔진으로 빌드된 JavaScript 런타임 환경 · 웹 브라우저 밖에서도 JavaScript를 실행할 수 있도록 하는 프로그램

1. JavaScript 런타임

  • 브라우저가 없어도 컴퓨터에서 JavaScript 실행 가능
  • 서버 프로그래밍, 데스크톱 앱, 명령줄 도구 개발 가능

2. 비동기 I/O

  • 동시에 여러 작업 처리 가능
  • 한 작업이 끝날 때까지 기다리지 않고 다른 작업 진행
  • 높은 성능과 효율성

3. 단일 스레드 이벤트 루프

  • 하나의 스레드로 많은 연결을 효율적으로 처리
  • 적은 메모리 사용량

4. NPM 생태계

  • 세계 최대 오픈소스 라이브러리 생태계
  • 100만개 이상의 패키지 사용 가능

CLI Command Line Interface

키보드로 명령어를 입력하여 컴퓨터와 상호작용하는 방식 · 짧은 텍스트 명령으로 파일 관리, 개발 도구 실행, 서버 작업 등을 빠르고 정확하게 자동화

CLI를 사용하는 이유

  • 속도 · 자동화 — 반복 작업을 스크립트 한 줄로 처리
  • 재현성 — 같은 명령을 실행하면 항상 같은 결과
  • 원격 작업 — 클라우드 · 서버 관리의 표준 도구
  • 개발 생태계 — Node / npm, Git, React, Express, Codex, Claude, Gemini 등 대부분 CLI로 구동

기본 용어

  • 터미널(Terminal) — 명령을 입력하는 프로그램 (예: macOS Terminal, Windows PowerShell)
  • 셸(Shell) — 명령을 해석하고 실행하는 엔진 (bash, zsh, PowerShell 등)
  • 프롬프트(Prompt) — 입력 대기 표시
  • 경로(Path) — 현재 위치(작업 디렉토리) · ~는 홈, .은 현재, ..은 상위

NPM과 NPX

NPM Node Package Manager

JavaScript 프로그래밍 언어를 위한 패키지 관리자 · 다른 개발자들이 만든 코드 조각(패키지)을 쉽게 내려받고 관리할 수 있도록 지원하는 도구

  • 패키지 설치 — 필요한 라이브러리나 도구를 쉽게 설치
  • 의존성 관리 — 프로젝트에 필요한 모든 패키지를 자동으로 관리
  • 스크립트 실행 — 프로젝트 실행, 빌드 등의 명령어 관리
  • 패키지 공유 — 자신이 만든 코드를 다른 개발자와 공유
npm --version
npm install [패키지명]

NPX Node Package eXecutor

패키지를 설치하지 않고 실행할 수 있도록 하는 npm 패키지 실행 도구

# Vite 프로젝트 생성 (4주차 실습)
npm create vite@latest my-project

# 설치 없이 일회성 실행
npx serve .
