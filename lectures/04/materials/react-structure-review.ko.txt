1. 검토 결론

중심 문제는 그림의 개수보다 설명 순서. 아직 보여주지 않은 화면·아직 정의하지 않은 개념을 학생이 알고 있다고 가정하고, 관찰할 현상을 표로 대체한 장이 반복됨.
현재 첫 본문 03번은 스터디 서비스의 버튼·잔여 인원·내 신청 목록을 보여주지 않은 채 일관성 문제를 설명. JavaScript로도 가능한 작은 갱신 사례만으로 React가 필요한 이유를 뒷받침하지 못함.
React의 역할은 14번에서야 설명하고, 컴포넌트 설명 전인 08번에서 React Native의 재사용을 소개. 16·18·20번은 관찰할 시계·입력창 없이 같은 현상을 반복하며 마지막에는 key·상태 초기화까지 범위를 확장.
설치와 Hello World의 마지막 네 장 중 24·25번은 문구 수정과 확인 절차가 중복.

3. 재구성 원칙

React의 역할 → 등장 배경과 활용 → 화면 관찰 → 설계 개념 → 갱신 원리 → 첫 실행.
사례를 사용하는 장은 학생이 볼 화면이나 실제 동작을 그 장 또는 직전 장에서 먼저 확보.
상품 검색 화면 하나로 구성 요소·재사용·데이터 변화·선언형 관점 연결. 2교시의 가상 스터디 서비스 맥락을 1교시에서 선행 학습시키지 않음.
새 사례는 관찰 목적이 달라질 때만 추가. 시계·입력창은 DOM 유지 관찰, Hello World는 실행 구조 확인이 목적.
기업 사례는 도입 맥락과 적용 범위를 설명. 특정 로딩 화면이나 생산성 수치를 React 자체의 효과로 일반화하지 않음.
화면과 관계를 설명하는 장에는 실제 화면·동작·구조를 사용. 통계·역할 비교에는 표 사용 가능. 모든 장을 표로 통일하지 않음.
본문에 후속 슬라이드 예고·제작 지시·검토 메모 노출 금지. 교시·챕터 상단 레이블을 다시 추가하지 않음.
별도 학생 실습 없음. 마지막 세 장은 강사 시연과 실행 흐름 소개. Props·State·Hooks·key API·세부 최적화 해설은 5주차 영역.
