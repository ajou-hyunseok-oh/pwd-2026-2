03. 웹 서비스 설계의 구성
해결할 문제와 사용 경험을 화면·기능·데이터로 구체화
기획 · UX · UI의 역할
서비스 기획 - 사용자 문제와 해결 방향의 설정
  - 서비스의 목적 · 해결 방법 · 범위 결정
UX - 목표 달성 과정에서 겪는 경험과 반응
  - 사용자 경험(User Experience)
UI - 사용자와 서비스의 상호작용 접점
  - 사용자 인터페이스(User Interface)

설계 요소의 연결

06. 프로젝트 개요 작성
목표·문제·사용자를 구분하여 설명하는 서비스의 출발점
개요의 세 요소
목표 - 문제 해결을 통해 만들고 싶은 사용자 변화
문제 정의 - 특정 상황에서 사용자가 겪는 불편
  - 설명 근거 - 사례 · 관찰 · 통계
타깃 페르소나 - 대표 사용자의 구체적인 모습
  - 배경 · 행동 · 목표 · 필요
문제 문장의 구성
사용자 + 사용 상황 + 달성하려는 목표 + 현재의 불편
원본 PDF: 10
강의 메모: 문제와 해결안의 구분을 말로 설명. 원본의 UGC 사례는 세 번째 챕터에서 작성 과정과 함께 사용. 가상 사례의 사업성이나 수치 검증을 수업 내용에 추가하지 않음.

07. 서비스 콘셉트 작성
사용자에게 제공할 가치와 핵심 이용 장면의 정의
콘셉트의 구성
서비스명 · 핵심 메시지 - 서비스의 특징을 전달하는 표현
  - 서비스명 · 한 줄 소개
핵심 가치 - 사용자가 서비스를 선택할 이유
  - 사용자에게 제공할 이점
메인 시나리오 - 핵심 가치를 얻는 대표적인 행동 순서
콘셉트 문장의 구성
대상 사용자 → 해결할 문제 → 제공할 방법 → 기대하는 변화
원본 PDF: 11, 5
강의 메모: 서비스명과 슬로건만으로 콘셉트가 완성되는 것은 아니며 사용자와 가치의 연결이 핵심. 작성 과정은 UGC 사례에서 시연.

08. 기능 목록과 우선순위
핵심 사용자 행동을 기준으로 결정하는 개발 범위
우선순위의 구분 예
구분 | 의미 | 선정 기준
P1 (핵심) | 첫 버전에 반드시 포함할 기능 | 주요 사용자 목표 달성에 필요한 기능
P2 (중요) | 사용 경험을 개선하는 확장 기능 | 핵심 흐름을 편리하게 만드는 기능
P3 (보완) | 출시 이후 추가할 부가 기능 | 추가적인 편의와 참여를 위한 기능
최소 기능 범위
MVP - 핵심 가치를 제공하는 첫 제품
  - Minimum Viable Product
  - 사용자 반응 확인이 가능한 최소 기능 범위
원본 PDF: 15
강의 메모: 원본 P1·P2·P3 분류 유지. 우선순위는 기능 이름에 고정된 정답이 아니라 프로젝트 목표와 개발 여건에 따른 선택. 가상 사례의 우선순위를 평가하거나 변경하지 않음.

09. 기술 구조와 배포 환경
화면·데이터 처리·저장·운영을 담당할 기술의 역할
기술 스택의 구성 예
구분 | 기술 | 역할
Frontend | React + Vite | 화면 구성과 사용자 인터랙션
Backend | Supabase | 인증 · PostgreSQL 데이터 저장 · 서버 기능
Deployment | Vercel · Supabase | 프론트엔드와 백엔드의 배포 · 운영
Design · Collab | Figma · Notion · GitHub | 화면 설계 · 문서 · 버전 관리
화면·API·DB의 관계
아이템 등록 화면 → 등록 요청(API) → 아이템 정보 저장(DB) → 등록 결과 표시
원본 PDF: 16, 24
강의 메모: 합의한 보완 2. 원본의 기술 스택과 API 구상을 역할 중심으로 유지. 요청 경로·응답 코드·테이블 설계는 이후 REST API와 DB 수업에서 구체화. 특정 기술 사용을 필수 과제 조건으로 추가하지 않음.

11. 가상 서비스의 사용자와 이용 맥락
NNN UGC Creator Hub · 제작자·구매자·운영자가 만나는 전시 서비스
역할별 목표와 현재 상황
역할 | 목표 | 현재 상황

구매자(Consumer) | 취향에 맞는 아이템 발견 | 아이템을 비교 · 탐색하는 데 시간 소요
운영자(Admin) | 전시 품질과 판매 과정 관리 | 신청 아이템 검토와 전시 배치가 필요
원본 PDF: 20, 10
강의 메모: 가상 서비스의 등장인물과 이용 맥락만 제시. 문제 문장과 가치 제안은 다음 장에서 도출한다.

13. 사용자 목표와 기능 도출
필요한 행동을 기능으로 표현하고 개발 우선순위를 부여하는 과정
목표 → 행동 → 기능
사용자 목표 | 필요한 행동 | 기능 | 우선순위

제작자의 전시 참여 | 등록 아이템으로 전시 신청 | 전시 신청 | P1
구매자의 아이템 발견 | 태그 · 테마별 탐색 | 큐레이션 피드 | P1
운영자의 전시 관리 | 신청 아이템 검토 | 승인 · 반려 | P1
제작자의 수익 확인 | 포인트 · 정산 내역 조회 | 포인트 정산 조회 | P2
원본 PDF: 15, 23
강의 메모: 합의한 보완 3. 원본 기능과 우선순위를 그대로 활용해 목표에서 기능 이름을 도출하는 과정을 설명. 기능 목록 전체를 다시 나열하기보다 도출 논리에 집중. 후기·좋아요 P3는 원본과 같은 확장 예시로 구두 설명.
