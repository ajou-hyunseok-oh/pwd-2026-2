02. 웹 서비스 설계와 AI 협업
사용자 문제·경험·기능을 정의하고 AI와 구현·검증하는 과정
설계 단계별 역할

문제·가치 | 질문·대안 비교 초안 | 실제 근거 확인·문제 선택

03. 타깃 사용자와 문제 정의
사용자·상황·목표·불편을 담은 구체적인 문제
교육용 사례 · 캠퍼스 스터디 모집
공강 시간에 참여할 스터디를 찾는 학생이 여러 모집 글의 시간과 모집 상태를 각각 확인해야 하는 불편
기획의 출발점
- 대상 · 참여할 스터디를 찾는 재학생
- 상황 · 자신의 시간표와 모집 조건을 비교하는 과정
- 문제 근거 · 실제 인터뷰·관찰을 통해 확인할 가설
강의 메모: 스터디 모집 사례 전체는 교육용 가정. 실제 이용자 불편이나 수요가 조사로 입증된 사례가 아님.

06. MVP와 기능 우선순위

08. 와이어프레임과 화면 명세

- 제목·주제 · 탐색한 모집 글의 식별

09. 화면 상태와 오류 복구
데이터와 요청 상태에 따른 표시·행동의 변화
신청 화면의 상태별 동작
상태 | 표시 | 가능한 행동
로딩 | 모집 정보 확인 중 | 신청 버튼 비활성
신청 가능 | 모집 조건·잔여 인원 | 참여 신청
처리 중 | 신청 처리 중·중복 클릭 방지 | 응답 대기
확정 | 참여 확정·신청 내역 | 내 신청 확인
오류·응답 불명 | 확정 여부 확인 중·재조회 | 내역 확인 후 재시도
강의 메모: 화면의 중복 클릭 방지만으로 서버 중복 저장이 방지되는 것은 아님. 데이터·API 슬라이드에서 저장 계층의 중복 제약과 연결.

10. 기능 요구사항과 완료 기준
기능의 입력·처리 규칙·결과를 관찰 가능한 조건으로 정의
참여 신청 · 선착순 확정 정책
항목 | 기능 명세와 확인 기준
입력·사용자 | 모집 글 선택 · 로그인한 학생의 신청
신청 가능 | 모집 중이며 잔여 인원이 있는 경우 참여 확정
이미 신청 | 같은 학생의 재신청으로 내역이 추가되지 않는 동작
모집 마감 | 신청을 저장하지 않고 마감 상태 안내
결과 확인 | 내 신청에 확정 내역 표시 · 새로고침 후에도 유지
강의 메모: 기능 요구사항과 수용 사례를 한 장으로 통합. 선착순 확정은 가상 서비스의 정책. 동시성 구현·테스트 상세는 제외. 완료 기준은 기존 수용 기준과 같은 의미로 설명.
근거: A3

13. AI 구현 계획 요청과 검토
기획 문서·화면·완료 기준을 전달하고 구현 전 계획 확인
요청 예시 · 참여 신청 기능
목표 · 참여 신청 기능의 구현 계획 작성.
맥락 · PRD·상세 화면·신청 완료 기준 참조.
제약 · 선착순 확정·중복 신청 금지·마감 시 신청 불가.
결과물 · 처리 순서·필요 데이터·검증 방법과 미결정 사항.

- 정한 정책·범위와 일치하는 기능

강의 메모: 공식 가이드 비교·맥락 설명·AI 요청 예시를 통합. 수업용 요청이며 실제 AI 실행 결과가 아님. 관련 설계 내용을 배운 뒤 요청 사례를 제시.

14. 기능 단위 개발 계획
작동 가능한 사용자 흐름과 검증 결과를 단계별로 확보
순서와 완료 기준 · 일정 예시
단계 | 작업 범위 | 완료 기준
1 · 탐색 | 샘플 데이터·목록·상세·필터 | 조건별 예상 목록과 일치
2 · 신청 | 인증·신청 저장·내 신청 | 새로고침 후 확정 내역 유지
3 · 모집 관리 | 등록·마감·권한 확인 | 주최자만 자신의 모집 관리
4 · 검증·배포 | 신청 실패·모바일·배포 확인 | 수용 기준 통과·서비스 URL 확인
강의 메모: 수업용 단계 예시. 주차·날짜·평가 배점은 확정하지 않음. 단계별 작업량을 산정하고 오류 수정 여유를 별도로 확보.
근거: A5

15. AI 구현 결과의 확인과 수정
완료 기준으로 실행 결과를 확인하고 재현 가능한 피드백 전달
확인할 결과
대상 | 확인 방법
사용자 흐름 | 브라우저에서 탐색 → 신청 → 내역 확인
예외와 저장 | 마감·재신청·새로고침 후의 결과 확인
수정 이후 | 같은 조건에서 재확인 · 변경한 기준과 결과 기록
구체적인 수정 요청 예시
마감된 모집 글에서 신청 버튼 클릭 → 신청이 저장되는 오류.
예상 동작: 저장 없이 마감 안내. 수정 후 정상 신청과 마감 신청을 함께 확인.
강의 메모: 구현 검증·오류 보고·작업 기록을 통합. 가상 오류 예시. 명령·지침 파일·검증 도구 사용법은 제외.
근거: A1, A3, A5

16. 서비스 성공 지표와 검증 계획
기능의 정상 동작과 사용자의 문제 해결을 각각 확인
평가 목적의 구분
목적 | 지표·판정 | 확인 방법
기능 완료 | 신청·중복 방지·정원 조건 충족 | 미리 정한 수용 사례 실행
사용자 가치 | 적합한 모집 글 탐색 시간·과업 성공 | 실제 대상 사용자의 과업 관찰
사용성 | 신청 상태 오해·도움 요청·이탈 이유 | 화면 이용 중 행동과 설명 기록
강의 메모: 서비스 지표는 수업용 적용. 목표값과 실제 측정값을 분리하고 참여자 수·과업·측정 조건을 기록. 자동 검사 통과를 사용자 수요 입증으로 해석하지 않음.
