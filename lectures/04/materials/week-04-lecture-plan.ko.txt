## 1. 강의의 연결 구조

학습 결과:
- 1교시: React의 등장 이유·활용 현황·UI 설계 철학·화면 갱신 원리를 구체적인 사례로 이해하고, 제공된 절차에 따라 프로젝트를 설치해 Hello World를 실행할 수 있는 상태.
- 2교시: 학생이 서비스 기획 원페이저 1페이지를 작성하고, 이를 바탕으로 기획 내용을 설명하는 5분 이내 동영상을 촬영할 수 있는 상태.
- 1교시의 설명 중심은 역사·통계·활용 사례·철학·VDOM. 설치·실행은 짧고 완결된 절차로 소개하며 별도 실습 없이 재현 가능한 조건 유지.

1교시: 등장 배경 → 역사·통계·실제 활용 → 컴포넌트와 선언형 UI → VDOM과 렌더링 → 개발 환경 → Hello World.
2교시: 사용자 문제 → 근거와 가치 제안 → MVP → 사용자 흐름과 화면 → 기능·데이터·기술 계획 → 원페이저 작성 → 발표 구성 → 5분 이내 동영상 촬영·확인.

두 교시의 연결: 1교시는 React의 기본 원리를 이해하고 실행 가능한 첫 프로젝트를 준비, 2교시는 만들 서비스의 근거와 범위를 정리해 원페이저와 영상으로 전달. 사용자 행동·화면·데이터를 연결하는 사고를 공통 축으로 사용.

공통 교육용 사례: 캠퍼스 스터디 모집 서비스.
- 1교시: 모집 카드와 목록을 통해 컴포넌트·데이터·화면의 관계 설명. 최종 시연 코드는 Hello World까지만 작성.
- 2교시: 조건 탐색 → 모집 글 확인 → 참여 신청 → 결과 확인의 한 흐름으로 기획 산출물 연결.
- 실제 운영 사례·조사 결과가 아닌 수업용 가정임을 명시. 통계·인터뷰·사용자 반응을 만들어 사실로 제시하지 않음.

1교시 완료 확인 기준:

- 생성한 프로젝트 폴더에서 의존성 설치 완료.
- npm run dev 실행 후 터미널에 표시된 로컬 주소로 접속.
- App.tsx를 수정해 브라우저에 Hello, World! 표시.
- 문구를 수정·저장한 결과가 화면에 반영되는지 확인.

### 챕터 08. 서비스 기획 원페이저와 발표 영상

맥락: 21~35번에서 설명한 설계 내용을 서비스 기획 원페이저 1페이지로 정리하고, 이를 설명하는 5분 이내 동영상을 촬영. 원페이저와 영상의 내용이 일치하도록 작성 → 발표 구성 → 촬영 → 확인 순서로 안내. 상세 PRD는 필요할 때 확장하는 참고 문서로만 언급하며 이번 필수 결과물에 포함하지 않음.

| 번호 | 제목 | 서브타이틀 | 맥락·설명 초점 |
|---|---|---|---|
| 36 | 서비스 기획 원페이저의 구성 | 사용자 문제와 서비스 구현 계획을 담은 한 페이지 | 최종 결과물인 원페이저와 5분 이내 발표 동영상을 먼저 명시. 원페이저 구성은 서비스명·한 줄 소개, 타깃·문제와 근거, 해결안·핵심 기능, 사용자 흐름, 기술·개발 계획, 기대효과·검증 방법. PRD는 상세화할 때의 참고 개념으로만 소개. |
| 37 | 서비스 기획 원페이저 작성 예시 | 문제·핵심 기능·사용자 흐름·개발 계획의 요약 | 캠퍼스 스터디 모집 사례로 한 페이지를 채우는 순서와 완성 예시 제시. 핵심 기능은 3개 내외, 사용자 흐름은 한 경로 중심으로 압축하는 작성 가이드. 실제 근거와 교육용 가정을 구분하고 긴 설명을 짧은 문장으로 정리. |
| 38 | 5분 이내 기획안 발표 구성 | 원페이저의 핵심을 설명하는 순서와 시간 배분 | 서비스·대상·문제 → 가치·핵심 기능 → 사용자 흐름 → 구현 계획 → 기대효과·검증 순서. 영상 길이는 5분 이내로 확정. 권장 설명 분량은 4분 40초로 잡고 화면 전환·마무리 여유 확보. 원페이저를 그대로 낭독하기보다 선택의 근거 설명. |
| 39 | 기획안 발표 동영상 촬영 | 원페이저 화면과 음성 설명을 담는 녹화 과정 | 화면 녹화와 음성 설명을 기본 방식으로 제안. 원페이저 열기 → 알림 정리 → 마이크·화면 영역 선택 → 시험 녹화 → 본 촬영. 글자 가독성·마우스 위치·음량 확인. 별도 슬라이드·완성 서비스 데모·얼굴 촬영을 필수화하지 않음. |
| 40 | 원페이저와 발표 동영상 최종 점검 | 한 페이지 기획 문서와 5분 이내 영상의 완성 확인 | 원페이저 한 페이지, 영상 길이 5분 이내, 서비스명·기능·범위 일치, 읽을 수 있는 화면, 들리는 음성, 시작부터 끝까지 정상 재생 확인. 링크 방식이면 열람 권한도 점검. 제출일·파일 형식·제출 경로는 확정된 안내에 맞춰 반영. |

발표 동영상 길이: 5분 이내(확정). 아래 시간 배분은 4분 40초를 목표로 한 구성 예시이며 나머지 20초는 전환·마무리 여유:
- 0:00~0:45: 서비스명·타깃 사용자·문제의 근거
- 0:45~1:20: 기존 대안과 핵심 가치
- 1:20~2:50: 핵심 기능·사용자 흐름·화면 구상
- 2:50~4:00: MVP·기술 구조·개발 계획
- 4:00~4:40: 기대효과·검증 방법·마무리

촬영 전 기획 내용 점검 질문:
- 이 사용자가 실제로 겪는 문제라는 근거
- 기존 대안을 두고 이 서비스를 선택할 이유
- 기간 안에 반드시 구현할 핵심 기능
- 필요한 데이터·외부 API의 확보 방법
- 정상 동작과 사용자 가치의 확인 방법

확정 결과물: 서비스 기획 원페이저 1페이지 + 기획안 발표 동영상 1개(5분 이내).
촬영 방식 제안: 원페이저를 화면에 띄우고 음성으로 설명하는 화면 녹화. 얼굴 노출·특정 녹화 프로그램·추가 발표 슬라이드는 필수 조건으로 두지 않음.
촬영 절차: 원페이저 완성 → 설명 순서와 시간 배분 작성 → 짧은 시험 녹화로 화면·음성 확인 → 전체 촬영 → 최종 파일 재생 확인.
결과물 확인: 원페이저가 한 페이지인지, 화면에서 내용을 읽을 수 있는지, 영상 전체 길이가 5분 이내인지, 음성이 명료하고 설명이 끝까지 포함되는지, 두 결과물의 서비스명·핵심 기능·범위가 일치하는지 확인. 링크로 제출하는 경우 열람 권한도 확인.
제출일·파일 형식·제출 경로·평가 배점·개인 또는 팀 운영 여부는 확정 후 별도 안내에 반영. 작년 개인 프로젝트 규정을 올해 규정으로 복사하지 않음.

## 6. 2026년 반영 사항과 정확성 기준

1. React: 확인일 공식 Versions 페이지는 19.3을 최신으로 표시. 강의는 React 19 계열의 기본 개념 중심으로 구성하며 신기능 API 나열은 하지 않음. 2013년 최초 공개와 2019년 Hooks는 역사적 사실로 구분. [S1]
2. 시작 도구: Create React App은 2025-02-14 신규 앱용으로 deprecated. 공식 문서의 프레임워크 권장과 기초 학습용 Vite 경로를 함께 설명. [S12, S13]
3. Vite: 확인일 문서의 Node 요구사항은 20.19+ 또는 22.12+이며 일부 템플릿은 더 높은 버전을 요구할 수 있음. 이는 호환 하한 설명이고, 지원 종료 여부를 검토하지 않은 오래된 Node 버전을 추천하는 의미가 아님. 수업 시연용 지원 버전은 시연 준비에서 확정. 빌드 엔진을 과거의 Rollup으로 고정해 설명하지 않음. [S14]
4. 통계: 2026년 결과 페이지는 이번 확인에서 확보하지 못했으므로 2025년 공식 조사 사용. ‘2026년 시장점유율’로 재명명하지 않음. 전문 개발자 해당 문항 응답 19,460명, 복수 기술 사용 가능, 지난 1년간 사용 경험 기준. React 46.9%는 이 집단의 응답 비율. 전체 응답자 React 44.7%와 혼합 금지. 원본 페이지 내 Professional Developers 그래프와 표본 수를 직접 확인. [S3]
5. 비교 범위: 원본의 목록은 전체 웹 기술 순위가 아님. Next.js는 React와 함께 쓰일 수 있어 독립적인 대체재 점유율처럼 더하지 않음. 필요하면 Next.js 21.5%를 생태계 보조 정보로만 표시. [S2, S3]
6. VDOM: ‘직접 DOM은 전체 렌더링, React는 항상 더 빠름’이라는 비교 제거. UI 계산과 실제 DOM 반영을 구분하고 브라우저 layout·paint를 Commit 자체의 작업으로 묶지 않음. [S10]
7. 사용 사례: Instagram은 공식 2024년 웹 적용 공개 사례, Shopify는 React Native 공식 쇼케이스의 모바일 사례로 출처 시점을 구분. 현재 모든 화면의 구현 방식까지 확인한 것으로 확대하지 않음. [S4, S5]
8. 설계 사례 수치: 원본 p.10의 ‘4천만 개·판매율 1% 미만·62%’는 이 자료만으로 원 조사와 방법을 검증할 수 없으므로 재사용하지 않음. 원본의 40% 정산도 일반적인 수익 배분 규칙처럼 설명하지 않음.
9. 디자인 도구: Adobe는 XD를 maintenance mode로 안내. 도구 비교를 크게 늘리지 않고 와이어프레임의 목적을 중심에 둠. [S17]
10. AI 보조 기획: 아이디어·화면 초안·질문 목록 작성에 활용하는 선택지는 포함하되, 생성 결과를 실제 인터뷰·시장 통계·검증된 요구사항으로 취급하지 않음. 사용자 근거와 가정을 분리하는 기존 설계 원칙의 적용. [S16]
11. 학생 프로젝트 검증: MAU·매출 같은 운영 지표 목록보다 과업 성공·시간·오류 등 실제 수업에서 검증 가능한 지표를 우선하는 교육적 제안. 사용 시간이 길수록 항상 좋은 경험이라는 식의 설명 제외.
